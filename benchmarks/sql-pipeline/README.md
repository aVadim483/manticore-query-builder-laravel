# Разделение подготовки SQL и выполнения запросов

[Результаты и гипотезы оптимизации](results-2026-10-26.md).

[Реализованная пакетная подготовка INSERT/REPLACE](batch-writes.md) сравнивает прежнюю 4.x,
новый штатный путь и совместимую компиляцию пользовательской Grammar. Для этого сравнения
используется batch-writes.py со штатными классами без подмены Grammar таймерами.

Дополнительное [A/B-сравнение строковых float и Expression для INSERT/REPLACE](float-string-writes.md)
проверяет именно стоимость отказа от числовых Expression при сохранении остального пути записи.

Стенд использует две отдельные установки Laravel с одинаковыми общими зависимостями:
опубликованную 3.0.0 и опубликованную 4.0.0. Текущая 4.x и каждый прототип подключаются
отдельным автозагрузчиком из снимка `composer.json` + `src/`; установленные vendor не меняются.
Путь и SHA-256 действительно загруженного класса проверяются при запуске.

Нужны PHP 8.3+ с PDO MySQL, Python 3.10+, локальный Manticore с KNN на `127.0.0.1:19306`
и права на создание/удаление случайных `pipe_*` таблиц. Приложения должны иметь CLI-обёртку
`bin/php`, конфигурацию соединения manticore без префикса и отключённое прикладное логирование.
Стенд повторно использует `../compare-versions/adapter.php` и `fixtures.php`; сохраняйте
эту структуру каталогов при копировании на тестовый сервер.

```sh
python3 make-variants.py --source /path/to/source-snapshot --output /path/to/new-variants
python3 run.py --v3 /path/to/v3-app --v4 /path/to/v4-app \
  --source /path/to/source-snapshot --variants /path/to/new-variants \
  --output /path/to/results.json --samples 30 --build-rounds 15 --documents 20000
python3 check-variants.py --app /path/to/v4-app \
  --source /path/to/source-snapshot --variants /path/to/new-variants \
  --output /path/to/checks.json
python3 render.py --raw /path/to/results.json --checks /path/to/checks.json --output .
```

Каталог вариантов должен быть новым: генератор отказывается перезаписывать существующий
снимок. `--only knn20 write_insert500 write_update_float` позволяет проверить часть сценариев;
полный отчёт формируется для полного прогона. Для короткой проверки стенда используются
`--samples 5 --build-rounds 3 --documents 2000`.

Режимы измерения:

| Режим | Что измеряется |
| --- | --- |
| `build` | Подготовка до первого PDO-вызова; запрос останавливается до выполнения, SQL сверяется с реальным |
| `live` | Реальная операция с отметками компиляции, PDO prepare/bind/execute/fetch и CPU-времени |
| `replay` | Перехваченные SQL и bindings повторяются через PDO без билдера |
| `literal` | Выполняется фактический SQL из PDO Sent SQL без повторной привязки параметров |
| `plain` | Полная операция с отключённой трассировкой, контроль реального выигрыша |

SQL, параметры и типы захватываются отдельно перед сериями. Захват и `debugDumpParams`
не входят в измерения. Очистка/заполнение таблиц и проверка результатов вынесены за таймер.
Для всех выполняемых операций проверяются хеши нормализованных результатов или состояния
записанных документов. Параметры, переменные окружения и SQL main-приложения не копируются.

В исходных данных находятся все отдельные измерения, перехваченные SQL/bindings, манифесты
исходников и сведения об окружении. Сводка сокращает эти данные для чтения. Проверки
прототипов включают cold-schema события и наследование, отсутствующие в прогретом бенчмарке;
совпадение результатов основного набора не считается доказательством полной совместимости.

`verify-environment.py` предназначен для существующего приложения проверки миграции
этого проекта. Он сверяет vendor по манифесту опубликованного 4.0.0, отпечаток 2105
документов и отсутствие оставшихся `pipe_*` таблиц:

```sh
python3 verify-environment.py --apps /path/to/migration-test-apps --output environment-validation.json
```

Все изменения алгоритмов остаются экспериментами в отдельных снимках. Для переноса
кандидата в библиотеку нужны сохранение точек расширения, тесты поддерживаемых версий
и новый A/B-прогон. Скрипты не устанавливают, что оставшееся отставание неизбежно.
