# Профиль пакетных INSERT/REPLACE

После оптимизации построения SQL выполнены [повторные замеры](optimized-results-2026-10-26.md)
с отдельным снимком исходников, опубликованными 3.0.0 и 4.0.0. Ниже сохранён исходный профиль.

26 октября 2026 года проверены опубликованные **3.0.0** и **4.0.0** на том же сервере,
что использовался для [A/B-сравнения](../compare-versions/results-2026-10-26.md): PHP 8.3.6,
Laravel 12.70.1, Manticore 29.9.0, локальный TCP. Xdebug отключён. Схема и соединения прогреты,
логирование запросов отключено. Создавались только случайные отдельные таблицы.

Основной источник дополнительных затрат — **`NumericBindings::prepare()`**. Для 500 строк
он занимает около **13 мс**, примерно 24% времени 4.0 и 61% разницы с 3.x. Оставшаяся разница
не исчезает после его ускорения: участвуют преобразование значений, работа с bindings,
построение SQL и проверки формы записи.

## Разложение времени

Медианы десяти измерений после трёх прогревочных запусков. В каждой строке таблицы ниже
показано собственное время этапа: вложенные вызовы не складываются повторно.

| Этап INSERT 500 строк | 4.0, мс |
| --- | --- |
| `NumericBindings::prepare()` | 13,07 |
| Преобразование значений `encodeWriteRows()` | 4,06 |
| `cleanBindings()` | 2,71 |
| Построение SQL `compileInsert()` | 1,75 |
| Остальная работа билдера: проверки, сортировка, flatten и вызовы | 2,97 |
| `prepareBindings()` + `bindValues()` | 1,10 |
| PDO prepare | 0,01 |
| PDO execute: клиентское экранирование, сеть и Manticore | 28,42 |
| **Полный INSERT** | **54,20** |

У 3.x полный INSERT занимает **32,97 мс**: примерно 25,99 мс — PDO execute, 6,42 мс —
остальная подготовка и 0,56 мс — дополнительное получение последнего ID. Для REPLACE
получена та же картина: 32,95 мс у 3.x против 54,10 мс у 4.x, NumericBindings — 13,02 мс.
Медианы отдельных этапов могут не суммироваться точно в медиану целого.

PDO execute не является чистым временем сервера: в него входит эмуляция prepared statements
на стороне PDO. Эти замеры не отделяют CPU Manticore от клиентского экранирования и сети.

## Почему числовые bindings дороги

PDO не имеет PARAM_FLOAT. Драйвер оставляет строки и остальные значения связанными, а
конечные float подставляет в SQL как числовые литералы. Текущий
[`NumericBindings`](../../src/Manticore/Laravel/Database/NumericBindings.php) проходит SQL
посимвольно на PHP, различая placeholders, кавычки, идентификаторы и комментарии.

В пакете из 500 документов получились **14 612 байт SQL, 3000 параметров, 500 float**.
После преобразования остаются 2500 связанных параметров. Время данного этапа в профиле:
2,68 мс для 100 строк, 13,07 мс для 500 и 23,94 мс для 1000. На этих размерах рост
приблизительно линейный; квадратичная сложность измерением не установлена.

Причина проверена отдельным контролем: одинаковые хранимые цены `1.0, 2.0, …` передавались
сначала как PHP float, затем как PHP int. Данные после записи совпали.

| INSERT 500, эквивалентные целочисленные цены | Полное время 4.0 | NumericBindings |
| --- | --- | --- |
| PHP float | 53,94 мс | 12,84 мс |
| PHP int | 41,41 мс | 0,25 мс |

Это контроль механизма, а не способ ускорить произвольные дробные значения изменением их типа.

## Изолированный прототип

В `prototype.php` проверен обход SQL через PCRE с callbacks только для токенов вместо
цикла PHP по каждому символу. Он сохраняет float-проверки, кавычки, комментарии,
позиционные и повторяющиеся именованные параметры; строки продолжают передаваться через bindings.
Прототип подключался только явным параметром профилировочной копии Connection. Код `src`,
vendor и публичное приложение не изменялись.

Внутри полного REPLACE 500 с одинаковыми включёнными пробами время NumericBindings
сократилось с **13,04 до 3,22 мс**. Отдельный прогретый микроцикл на восстановленных из JSON
параметрах дал 7,36 → 1,82 мс; эти абсолютные значения не подставляются в профиль полного пакета.

Практический эффект проверен отдельно, с отключёнными таймерами этапов, тремя прогревами,
десятью измерениями и чередованием 3.x, исходной 4.0 и прототипа:

| Операция | 3.0 | Исходная 4.0 | 4.0 с прототипом |
| --- | --- | --- | --- |
| INSERT 100 | 7,85 мс | 11,85 мс | 9,89 мс |
| REPLACE 100 | 7,72 мс | 11,82 мс | 9,85 мс |
| INSERT 500 | 33,35 мс | 54,63 мс | 44,88 мс |
| REPLACE 500 | 33,15 мс | 53,99 мс | 44,39 мс |
| INSERT 1000 | 63,84 мс | 100,30 мс | 85,25 мс |
| REPLACE 1000 | 64,15 мс | 99,34 мс | 84,33 мс |

На 500 строках это уменьшение полного времени примерно на **18%**. Отставание от 3.x
остаётся около 34–35%; ускорения одного renderer недостаточно для полного устранения разницы.

Проверки прототипа: **10 011** дифференциальных случаев против исходного renderer на PHP
8.3 и 8.4; существующие **5 тестов / 7 assertions** NumericBindings; совпадение всех документов
после реальных INSERT/REPLACE, включая контроль float/int. Прототип не включён в библиотеку.
Для внедрения нужны расширение регрессионных тестов и полная матрица поддерживаемых версий.

## Следующие места для оптимизации

1. Перенести проверенную идею в NumericBindings с сохранением исходного SQL/bindings в событиях
   и исключениях, затем выполнить полный набор тестов.
2. Отдельно проверить `cleanBindings()` и проходы по массивам: они дают около 2,7 мс на пакет.
3. Проверить повторную сортировку и проверки формы пакета, сохраняя защиту от неверных колонок,
   JSON-путей и неподдерживаемых условий. Преобразование JSON/MVA занимает ещё около 4 мс.

Отключение валидации и подстановка строковых значений в SQL не использовались как оптимизация.

## Воспроизведение

Нужны две закрытые копии приложений из [методики A/B](../compare-versions/README.md),
PDO MySQL, Python 3 и CLI-обёртка `bin/php`. В этом сценарии адрес — 127.0.0.1:19306.

```sh
python3 benchmarks/profile-writes/run.py --v3 /path/v3 --v4 /path/v4 --output /tmp/profile.json
python3 benchmarks/profile-writes/run.py --v3 /path/v3 --v4 /path/v4 --output /tmp/prototype.json --prototype
python3 benchmarks/profile-writes/run.py --v3 /path/v3 --v4 /path/v4 --output /tmp/timed-prototype.json --prototype --prototype-profile
php benchmarks/profile-writes/check-prototype.php /path/v4/vendor/autoload.php
```

Профиль снимается переопределениями методов, делегирующими вызовы исходной реализации,
и общим PDO-подклассом. В v4 точный вызов числового renderer обёрнут таймером на уровне
Connection. Время подготовки схемы, генерации данных, очистки таблиц и проверочного SELECT
исключено. Вложенные этапы имеют inclusive/exclusive время. Пробы не устанавливаются в приложение.

Параметры isolated-microbenchmark можно получить через `capture-input.py`, затем передать
`render-benchmark.php`. Для существующих unit-тестов доступен отдельный `prototype-bootstrap.php`:
он подменяет класс только в запущенном процессе PHPUnit, а не в библиотеке.
