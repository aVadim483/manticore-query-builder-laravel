# 4.0.0-alpha.2

[Русский](../ru/releases/4.0.0-alpha.2.md)

Native parent-driver APIs for downstream Scout integration, available independently of Scout.
This remains an alpha. Scout integration itself is not verified by this release.

* Independent text/vector candidate searches with weighted RRF, deterministic ID tie-breaking,
  branch metadata snapshots and `HybridResult` window pagination/totals. Existing
  `knn()->match()` retains intersection semantics.
* Maintenance-only local RT index replacement: empty CREATE LIKE staging, explicit three-name
  state inspection, forward/rollback recovery and no automatic old-index deletion. There is
  an observable rename gap; no atomic swap or zero-downtime guarantee. Distributed tables,
  clusters and read/write splitting are excluded.
* Lazy per-connection server/module evidence, bounded read-only operation probes, preserved
  failure causes and HNSW dimension/metric validation. No mandatory registration-time SQL.
* Extended Schema Builder accumulated since alpha.1: ordered ALTER settings and inspection,
  validated row-wise int-to-bigint `change()` and Buddy table rename.

See the [full API and Scout handoff contract](../hybrid-and-index-replacement.md),
[schema guide](../schema-alter.md) and [3.x migration guide](../upgrading-3.x-to-4.x.md).

## Validation and installation

The full suite passed on PHP 8.4.19 with Laravel 11/12/13 against Manticore 28.6.6 and
Laravel 13 against 29.9.0: **160 tests / 870 assertions** per run, without skips. Production-only consumers passed
on both servers, including hybrid/probes/clone/switch/rollback. Separate-process readers,
injected interruptions and actual second-rename SQL failures verify replacement limits.
The no-Buddy check verifies explicit unavailable fuzzy/autocomplete evidence and rename errors.
The release must pass the existing eight-job PHP 8.2/8.3/8.4/8.5 × minimum/latest CI matrix
before publication. The standalone PHP builder remains absent.

```sh
composer require avadim/manticore-query-builder-laravel:4.0.0-alpha.2
```

Alpha.1 callers can keep existing APIs; fusion uses a new result type and requires explicit
window totals in downstream serializers. Schema widening has no automatic reverse conversion.
Applications must handle imports, embeddings, queues, locks, write reconciliation and retained
index cleanup. No implicit fallback changes search semantics. The live 3.x-to-alpha.1 demo
migration report remains historical evidence; it is not a Scout or alpha.2 application test.
