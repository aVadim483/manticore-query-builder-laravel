# Float-параметры как строки: проверка Manticore

[English](../float-string-bindings.md)

26 октября 2026 проверены **Manticore 28.6.6 и 29.9.0**, PHP 8.3.6, PDO MySQL.
На каждом сервере выполнены 57 сценариев: 48 с включённой эмуляцией prepared statements,
как в драйвере, и девять диагностических с native prepares. Варианты передачи: числовой
литерал через текущий NumericBindings, строка через JSON-форматирование, обычное PHP-приведение
float к строке и, где задано, DOUBLE(?) в SQL. Проверялись исключения, фактические строки,
типы результата, affected rows и предупреждения. Результат классификации совпал на обоих серверах.

## Результат при emulated prepares

| Контекст | Строковый float |
| --- | --- |
| INSERT/REPLACE в обычный float-атрибут | Совпадает с литералом для всех восьми проверенных значений |
| UPDATE float-атрибута | Запрос успешен, affected rows = 0, значение не меняется |
| WHERE по float: `=`, `>`, отрицательное значение, экспонента | Ошибка `unsupported filter type 'string' on attribute 'price'` |
| BETWEEN по float | Синтаксическая ошибка: ожидается число |
| Числовой фильтр JSON | Принимается, но выдача отличается: в проверках строковый вариант вернул пустой результат |
| SELECT числового параметра, арифметика | Синтаксическая ошибка |
| ABS, POW, GEODIST, DOUBLE со строковым литералом | Ошибка типа аргумента: строка не принимается как число |
| SUM выражения, HAVING по числовому агрегату | Ошибка |
| UPDATE отдельного числового JSON-пути через raw SQL | Синтаксическая ошибка |
| Векторный tuple в INSERT/REPLACE и KNN | Синтаксическая ошибка на строковых компонентах |
| IF с проверенным сравнением | Результат совпал; это частный работающий контекст |

Проверенные значения записи: 55.3, -55.3, 0.0, -0.0, 1e-7, 1e-20, 1.25e6 и 1e20.
Различия float32-представления, например 55.299999 при чтении 55.3, одинаковы в обоих
вариантах INSERT/REPLACE. Обычная PHP-строка и JSON-форматированная строка дали одинаковую
классификацию на этих примерах.

## UPDATE может пройти без изменения данных

При исходной цене 1.0:

```sql
UPDATE products SET price=55.3 WHERE id=100;   -- price становится 55.299999
UPDATE products SET price='55.3' WHERE id=100; -- price остаётся 1.0
```

Это два отдельных запуска с восстановлением исходной строки перед каждым запросом.
Во втором PDO execute вернул успех, affected rows — 0, SHOW WARNINGS — пустой результат.
Одной проверки отсутствия исключения недостаточно.

Для JSON-числа `details.rating=1.25` числовое условие `details.rating=1.25` нашло четыре
документа, а `details.rating='1.25'` не нашло ни одного. Смена типа параметра меняет смысл фильтра.

Обёртка DOUBLE(?) не стала универсальным решением: `DOUBLE('55.3')` отклоняется как строковый
аргумент, а в INSERT/UPDATE дополнительно ограничен допустимый синтаксис значения.

Один случай — IN с дробными значениями на float-атрибуте — не поддерживался и с исходным
числовым литералом. Он отмечен отдельно и не используется как доказательство регрессии от строки.

## Native prepares

Диагностические native prepares не меняют действующий контракт Connector: эмуляция остаётся
обязательной. На обоих проверенных серверах UPDATE с литералом 55.3 при native prepare
сохранил 55.0; строковый вариант оставил старое значение. Эти случаи не являются рекомендацией
переключать режим подготовки запросов.

## Вывод для оптимизации

Глобально удалять NumericBindings и превращать все float в строки нельзя. Нельзя также
пропускать обработку для любого SQL, начинающегося с INSERT/REPLACE: параметры могут находиться
внутри векторного tuple, где нужны именно числа.

Возможен отдельный быстрый путь для **проверенных скалярных float-значений, записываемых
обычным билдером в INSERT/REPLACE**. Он должен учитывать расположение параметров, сохранять
обработку векторов/выражений и проверку конечности чисел, а также контракт событий и исключений.
UPDATE, фильтры и выражения требуют сохранения числового типа. В рамках этой проверки код
библиотеки и vendor не изменялся; оптимизация не внедрялась.

Из клона репозитория:

```sh
php tests/experiments/float-string-bindings.php /path/to/application/vendor/autoload.php 9306 /tmp/float-strings.json
```

Скрипт создаёт случайную таблицу с префиксом `float_binding_` и удаляет её в finally.
Поле `ok` в исходном отчёте означает завершение эксперимента, а не успешность каждого SQL-варианта:
ошибки и различия сохранены в отдельных режимах каждого случая. Использовались изолированные
тестовые серверы; публичное приложение не переключалось и его данные не изменялись.
