# Проверка миграции живого Laravel-приложения: 3.x → 4.x

Приложение на [manticore.avadim.ru](https://manticore.avadim.ru/) сначала развёрнуто с **3.0.0**,
проверено через браузер и CLI, затем переведено на опубликованную **4.0.0-alpha.1** по
[руководству перехода](upgrading-3.x-to-4.x.md). Сейчас сайт работает на 4.x.
Установленные пакеты не редактировались. Это настоящее Laravel-приложение на сервере хостинга,
а не Testbench. Данные демонстрационные; Scout не подключался и не проверялся.

[Страница проверок](https://manticore.avadim.ru/?view=checks) и
[JSON-отчёт](https://manticore.avadim.ru/?report=1) показывают результаты до и после перехода.
Через формы можно создать, изменить и удалить свой тестовый документ. Формы не дают менять
исходный каталог и документы других сессий.

CLI приложения загружает отдельный модуль PDO SQLite: системный PHP хоста его не включает.
Веб-запросы используют Manticore, файловые сессии и кэш. Код, vendor, конфигурация, SQLite и логи
находятся вне web-root. Из-за нестабильного доступа сервера к Packagist зависимости разрешены
локально; lock-файл перенесён, и Composer установил на сервере точные закреплённые релизы.

Исходное приложение сохранено в отдельном Git-репозитории как `baseline-v3` (коммит `fb40b3a`),
переведённое — как `migrated-v4-alpha1`. Базовый отчёт сохранён без изменений. Все 31 сравнимых
результата приложения совпали с исходными SHA-256 после явного преобразования DTO.
Оставшийся сценарий проверяет ожидаемую смену Row/Generator на stdClass/LazyCollection.

32 сценария охватывают выборку колонок, MATCH и бренд, фасеты/подсветку, составные значения,

Проверочные таблицы и документы отделены от исходного каталога.

11 браузерных сценариев проверяют приложение через PHP-FPM: главную и результаты, MATCH

без горизонтальной прокрутки. Снимки desktop/mobile сохранены до и после перехода.

Шесть дополнительных проверок: отсутствие старой зависимости, один SELECT cursor для всех
2105 ID, курсорная пагинация по 29 страницам без потерь/повторов, точный total групп,
QueryException при ошибках чтения/записи и чистые миграции с откатом. Для последнего используются
отдельный SQLite-файл и префикс Manticore: четыре миграции выполняются и откатываются, включая
реальную новую Blueprint-схему приложения. Рабочая таблица при этом не удаляется.

## Какие изменения приложения понадобились

* Конфигурация перенесена в `database.connections`, физический префикс сохранён; маркеры `?`,
  старый конфиг и вызовы фасада/менеджера удалены.
* ID перенесены из аргументов в документ или WHERE; `findOrFail()` заменён на
  `where()->firstOrFail()` с перехватом `RecordNotFoundException` в единственном числе.
* Колонки передаются массивами. Добавлен явный `withScore()`, использованы метаданные/фасеты
  `search()`, `withHighlight()` и CALL-помощники соединения. Порядок аргументов KNN изменён.
* В DTO сохранён прежний JSON-контракт: место score, псевдоним фасета `_count`, целые числовые
  поля CALL. Классы совместимости в пакет не добавлялись.
* JSON-путь переведён на `whereRaw('details.color = ?', ['red'])`: обычное Laravel-обращение
  с точкой иначе добавляло префикс к `details` как к имени таблицы.
* Старый `cursor(700)` заменён на `lazy(700)` для сохранения постраничного чтения; задан порядок.
  Новый `cursor()` одним SELECT отдельно проверен с явным лимитом 2105 строк.
* Поддерживаемый DDL перенесён на Schema Builder. Старые MODIFY/rename/настройки выполнены
  явными ALTER, подтверждёнными сервером, как допускает руководство.
* Логирование переведено на события, используются Laravel purge/reconnect. Пересобраны кэши
  конфигурации и представлений, выполнен `queue:restart`. Проверочные задания идут в отдельные
  очереди, worker запускается с force, если приложение временно находится в режиме обслуживания.

UPDATE на месте **не откатывается** транзакциями Manticore. Исходная проверка выявила это
существующее ограничение сервера; для rollback используется INSERT, примеры транзакций
исправлены на полную замену документа REPLACE.
См. [документацию Manticore](https://manual.manticoresearch.com/Data_creation_and_modification/Transactions).

Результат подтверждает переход этого приложения на перечисленных версиях. Он не подтверждает
совместимость Scout-адаптера, сохранения моделей Eloquent, Lumen или любых других приложений.
