# Возможности сервера и замена RT-индекса

[English](../hybrid-and-index-replacement.md)

API диагностики и замены индекса добавлены в alpha.2.
См. также [Schema Builder](schema-alter.md) и [контракты API](../parent-search-contracts.md).

## Независимые текстовая и векторная ветви

Гибридному поиску посвящено [отдельное руководство](hybrid-search.md): простейший вызов,
первый документ, фильтры, веса, метаданные, пагинация и расширенные опции.
В alpha.3 используются hybridSearch()/hybridGet()/hybridFirst(); инструкция перехода с alpha.2 находится там же.

## Явная проверка возможностей

```php
$info = $db->capabilities(); // ленивый SHOW STATUS, снимок конкретного соединения
$version = $info->version;
$installed = $info->advertises('knn'); // наличие модуля, не доказательство работы запроса
$evidence = $db->probeCapability('knn', 'products', [
    'column' => 'embedding', 'vector' => [1, 0, 0],
]);
$works = $evidence->supported;
$cause = $evidence->cause; // исходный QueryException либо UnsupportedFeatureException
$db->forgetCapabilities();
```

Проверки только читают выбранную вызывающим кодом таблицу. Имена: `knn`, `fuzzy`,
`autocomplete`, `keywords`, `suggest`, `qsuggest`. KNN принимает column/vector, остальные — text.
Успех подтверждает лишь операцию с этими параметрами и таблицей на этом соединении, даже
если таблица пуста; качество поиска и другие параметры/плагины он не проверяет.
Если сервер не сообщает Buddy, fuzzy/autocomplete отмечаются недоступными без запуска операции.
Явная ошибка зависимости сохраняется в отрицательном результате вместе с исходным исключением;
прочие SQL-ошибки, отсутствие таблицы и сетевые ошибки выходят без подмены.
Загруженные модули автоматически не превращаются в положительный результат проверки.
FIFO-кеш probes ограничен 128 записями на соединение. Он очищается при сбросе схемы,
disconnect/reconnect/purge и `forgetCapabilities()`. После внешнего изменения модулей/настроек
обновляйте его явно. Регистрация провайдера не выполняет SQL; обычные запросы не получают
обязательных проверок возможностей.

## Замена RT-индекса в режиме обслуживания

```php
use Illuminate\Support\Facades\Schema;

$schema = Schema::connection('manticore');
$definition = $schema->getCreateStatement('products');
$schema->createLike('products_next', 'products'); // только схема, без документов

// Приложение: импорт, догоняющие изменения, проверка, блокировка, остановка и дренирование трафика/очередей.
$replacement = $schema->replacement('products', 'products_next', 'products_previous');
$before = $replacement->inspect();
$after = $replacement->switch(maintenanceConfirmed: true);

// При той же политике обслуживания откат сохраняет новую версию в products_next.
$restored = $replacement->rollback(maintenanceConfirmed: true);
```

Три различных логических имени используют общий префикс соединения. Поддерживаются только
локальные RT-таблицы в RT-режиме на одном некластерном соединении. Distributed-таблицы,
кластеры и read/write splitting отклоняются. Переименование требует Buddy; объявленное наличие
Buddy не гарантирует успешную операцию. Ошибки сервера сохраняют `QueryException`.

| Наличие active / staged / backup | Состояние | Переключение | Откат |
| --- | --- | --- | --- |
| да / да / нет | `prepared` | active → backup, staged → active | уже восстановлено |
| нет / да / да | `gap` | staged → active | backup → active |
| да / нет / да | `switched` | уже переключено | active → staged, backup → active |
| другое | `conflict` | отказ | отказ |

Это **не атомарная операция и не zero downtime**. Читающий процесс на minimum/latest наблюдал
ошибки отсутствующей таблицы в промежутке и старые/новые данные до/после переключения.
Изоляция уже выполняющихся запросов через rename не гарантируется: дождитесь их завершения.
Параллельные записи, импорт, очереди, исключение двойного запуска и изменения после активации
согласует приложение. Boolean подтверждает эти условия, но не захватывает блокировку.
Перед откатом согласуйте записи, сделанные в новую версию индекса.

Драйвер не удаляет старую таблицу при успехе или ошибке. После сбоя прочитайте состояние
сервера и создайте объект с теми же именами; для `gap` явно выберите switch либо rollback.
Расположение имён не доказывает принадлежность таблиц и полноту импорта: храните идентификатор
операции/поколения, проверяйте данные и разрешайте конфликты в приложении.
Проверены искусственные прерывания и настоящий SQL-конфликт второго rename; обе версии
сохраняются для явного восстановления. Другие соединения сохраняют независимые кеши схемы.

CREATE LIKE сохраняет серверную схему, объявления HNSW и поддерживаемые настройки на том же
сервере. Он не переносит документы, внешние файлы, словари, плагины, embedding credentials/models
на другой сервер, членство в кластере и distributed-топологию. `getCreateStatement()` возвращает
серверный DDL, а не переносимый или очищенный от секретов экспорт; храните конфигурацию приватно.
Проверьте схему и зависимости staging до загрузки данных. Изменение local-цели distributed-таблицы
принято сервером при исследовании, но гарантии атомарности/чтения/записи в этом выпуске не доказаны,
поэтому API безопасного переключения через него не предоставляется.
