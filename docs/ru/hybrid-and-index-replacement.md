# Гибридный поиск, возможности сервера и замена RT-индекса

[English](../hybrid-and-index-replacement.md)

Добавлено после alpha.1 для **4.0.0-alpha.2**. Scout устанавливать не требуется.
См. [контракты](../parent-search-contracts.md) и [расширенный Schema Builder](schema-alter.md).
Семейство выполняющих методов `hybridSearch()`/`hybridGet()`/`hybridFirst()` ниже — ещё не
выпущенное изменение `dev-4.x` после alpha.2; в alpha.2 используется `hybrid(...)->search()`.

## Независимые текстовая и векторная ветви

```php
use Illuminate\Support\Facades\DB;

$db = DB::connection('manticore');
$result = $db->table('products')->where('stock', '>', 0)
    ->hybridSearch('phone', 'embedding', [1, 0, 0], [
        'text_weight' => 1, 'vector_weight' => 2, 'rank_constant' => 60,
        'text_candidates' => 100, 'vector_candidates' => 100,
        'knn_options' => ['ef' => 100],
    ]);

foreach ($result->hits() as $hit) {
    $id = $hit->id;
    $document = $hit->document;
    $score = $hit->score;
    // textRank, vectorRank, textScore и distance могут быть null.
}
$documents = $result->rows();
$page = $result->paginateWindow(perPage: 20, page: 2);
$totals = $result->totals();
```

Все три метода сразу выполняют поиск. Условия задаются на
обычном билдере до их вызова. Они не возвращают билдер и не требуют дополнительного `search()`.

| Метод | Возвращаемое значение |
| --- | --- |
| `hybridSearch($text, $column, $vector, $options)` | `HybridResult`: полное окно, оценки и метаданные |
| `hybridGet($text, $column, $vector, $options)` | `Collection<stdClass>`: документы в порядке итогового ранжирования |
| `hybridFirst($text, $column, $vector, $options)` | `stdClass|null`: лучший документ либо null при пустой выдаче |

`hybridGet()` возвращает те же документы, что `hybridSearch(...)->rows()`; при отсутствии
совпадений — пустую коллекцию. `hybridFirst()` ранжирует те же окна кандидатов и только затем
выбирает первый документ, не уменьшая лимиты ветвей до 1. Get/First используют типы
Collection/документ обычных Laravel-методов, без оценок, рангов и метаданных.
Для этих сведений и пагинации окна используйте `hybridSearch()`.

Обе ветви используют один write PDO и одинаковые атрибутные фильтры. Текстовая сортируется
по WEIGHT убывающе и ID возрастающе, векторная — по расстоянию и ID возрастающе.
Итоговая оценка: `text_weight/(rank_constant+text_rank) + vector_weight/(rank_constant+vector_rank)`.
Ранги начинаются с 1, отсутствующая ветвь даёт ноль. Повторяющиеся ID объединяются;
при пересечении данные документа берутся из текстовой ветви. При равной оценке используется
числовой порядок беззнакового ID с сохранением точности bigint. Исходные оценки и ранги
хранятся в `HybridHit`, поля документа не перезаписываются. Колонки с внутренними именами
`__hybrid_text_score` и `__hybrid_distance` запрещены.

По умолчанию: веса 1/1, константа 60, по 100 кандидатов, экранированный MATCH и пустые
`knn_options`. Веса — конечные числа 0..1000000, хотя бы один положительный; нулевой вес
отключает ветвь. Константа — целое 0..1000000, лимиты кандидатов — целые 1..10000.
Пустая текстовая строка пропускает текстовую ветвь. `escape => false` включает намеренный
расширенный синтаксис MATCH. Параметры KNN проверяются существующим `knn()`;
размерность и метрика HNSW читаются через SHOW CREATE TABLE. Cosine-вектор должен быть ненулевым.

Общий запрос должен содержать простое логическое имя таблицы и атрибутные AND-условия,
включая вложенные AND/MVA. Проекции, raw-условия/выражения, MATCH/KNN, фасеты, собственная
сортировка, лимиты, offset, joins, группировки, callbacks и другие формы отклоняются.
`fieldWeights()` и `ranker()` можно задать на общем запросе. Исходный билдер не меняется.
Существующий `knn()->match()` сохраняет семантику пересечения и не превращается в объединение.

`HybridResult` отличается от `SearchResult`: `windowTotal()` — точное число уникальных
кандидатов, `totalFound()` всегда null. `totals()` помечает точность окна как `exact`,
глобального total как `unavailable`, серверных totals ветвей как `unknown` либо `unavailable`
для отсутствующей ветви. `Meta` ветвей сохраняет исходные сведения сервера: на totals влияют
max_matches, cutoff и приближённый поиск; RAM KNN может сообщить больше совпадений, чем вернул top-k.
Суммировать totals ветвей или выдавать размер окна за полное число совпадений нельзя.

Метаданные захватываются до следующего запроса или query listener. Ошибка ветви выходит наружу,
успешного частичного результата и автоматической подмены режима нет. Ветви выполняются
последовательно без общего транзакционного снимка. `paginateWindow()` листает уже полученное
окно без SQL; новый поиск после изменения данных может вернуть другие страницы.
Обрезка кандидатов, приблизительный KNN и prefilter могут уменьшать или менять окно.
Глубокие страницы требуют большего явно ограниченного окна и дополнительных ресурсов;
неограниченного cursor нет. Большие документы и векторы увеличивают расход памяти и трафика.

## Явная проверка возможностей

```php
$info = $db->capabilities(); // ленивый SHOW STATUS, снимок конкретного соединения
$version = $info->version;
$installed = $info->advertises('knn'); // наличие модуля, не доказательство работы запроса
$evidence = $db->probeCapability('knn', 'products', [
    'column' => 'embedding', 'vector' => [1, 0, 0],
]);
$works = $evidence->supported;
$cause = $evidence->cause; // исходный QueryException либо UnsupportedFeatureException
$db->forgetCapabilities();
```

Проверки только читают выбранную вызывающим кодом таблицу. Имена: `knn`, `fuzzy`,
`autocomplete`, `keywords`, `suggest`, `qsuggest`. KNN принимает column/vector, остальные — text.
Успех подтверждает лишь операцию с этими параметрами и таблицей на этом соединении, даже
если таблица пуста; качество поиска и другие параметры/плагины он не проверяет.
Если сервер не сообщает Buddy, fuzzy/autocomplete отмечаются недоступными без запуска операции.
Явная ошибка зависимости сохраняется в отрицательном результате вместе с исходным исключением;
прочие SQL-ошибки, отсутствие таблицы и сетевые ошибки выходят без подмены.
Загруженные модули автоматически не превращаются в положительный результат проверки.
FIFO-кеш probes ограничен 128 записями на соединение. Он очищается при сбросе схемы,
disconnect/reconnect/purge и `forgetCapabilities()`. После внешнего изменения модулей/настроек
обновляйте его явно. Регистрация провайдера не выполняет SQL; обычные запросы не получают
обязательных проверок возможностей.

## Замена RT-индекса в режиме обслуживания

```php
use Illuminate\Support\Facades\Schema;

$schema = Schema::connection('manticore');
$definition = $schema->getCreateStatement('products');
$schema->createLike('products_next', 'products'); // только схема, без документов

// Приложение: импорт, догоняющие изменения, проверка, блокировка, остановка и дренирование трафика/очередей.
$replacement = $schema->replacement('products', 'products_next', 'products_previous');
$before = $replacement->inspect();
$after = $replacement->switch(maintenanceConfirmed: true);

// При той же политике обслуживания откат сохраняет новую версию в products_next.
$restored = $replacement->rollback(maintenanceConfirmed: true);
```

Три различных логических имени используют общий префикс соединения. Поддерживаются только
локальные RT-таблицы в RT-режиме на одном некластерном соединении. Distributed-таблицы,
кластеры и read/write splitting отклоняются. Переименование требует Buddy; объявленное наличие
Buddy не гарантирует успешную операцию. Ошибки сервера сохраняют `QueryException`.

| Наличие active / staged / backup | Состояние | Переключение | Откат |
| --- | --- | --- | --- |
| да / да / нет | `prepared` | active → backup, staged → active | уже восстановлено |
| нет / да / да | `gap` | staged → active | backup → active |
| да / нет / да | `switched` | уже переключено | active → staged, backup → active |
| другое | `conflict` | отказ | отказ |

Это **не атомарная операция и не zero downtime**. Читающий процесс на minimum/latest наблюдал
ошибки отсутствующей таблицы в промежутке и старые/новые данные до/после переключения.
Изоляция уже выполняющихся запросов через rename не гарантируется: дождитесь их завершения.
Параллельные записи, импорт, очереди, исключение двойного запуска и изменения после активации
согласует приложение. Boolean подтверждает эти условия, но не захватывает блокировку.
Перед откатом согласуйте записи, сделанные в новую версию индекса.

Драйвер не удаляет старую таблицу при успехе или ошибке. После сбоя прочитайте состояние
сервера и создайте объект с теми же именами; для `gap` явно выберите switch либо rollback.
Расположение имён не доказывает принадлежность таблиц и полноту импорта: храните идентификатор
операции/поколения, проверяйте данные и разрешайте конфликты в приложении.
Проверены искусственные прерывания и настоящий SQL-конфликт второго rename; обе версии
сохраняются для явного восстановления. Другие соединения сохраняют независимые кеши схемы.

CREATE LIKE сохраняет серверную схему, объявления HNSW и поддерживаемые настройки на том же
сервере. Он не переносит документы, внешние файлы, словари, плагины, embedding credentials/models
на другой сервер, членство в кластере и distributed-топологию. `getCreateStatement()` возвращает
серверный DDL, а не переносимый или очищенный от секретов экспорт; храните конфигурацию приватно.
Проверьте схему и зависимости staging до загрузки данных. Изменение local-цели distributed-таблицы
принято сервером при исследовании, но гарантии атомарности/чтения/записи в этом выпуске не доказаны,
поэтому API безопасного переключения через него не предоставляется.

## Переход с alpha.1 и контракт для Scout

Контракты обычных `search()`, `get()` и `first()` сохранены. Объединение возвращает `HybridResult`, а не
`SearchResult`; потребитель должен явно преобразовывать hits/documents и пагинацию окна.
Импорт Eloquent-моделей, генерация embeddings, UUID mapping, согласование очередей и Scout engine
в пакет не входят. Scout должен использовать точную проверенную alpha родителя и отдельно
проверить интеграцию после публикации.

## Переход с alpha.2 в dev-4.x

Замените `->hybrid($text, $column, $vector, $options)->search()` на
`->hybridSearch($text, $column, $vector, $options)`, чтобы сохранить полный результат с метаданными.
Если нужны только документы, используйте `hybridGet()` либо `hybridFirst()`.
Отдельный метод билдера `hybrid()` удалён без совместимого alias.
`HybridSearch` остаётся внутренним исполнителем; обычные `search()`, `get()` и `first()`
сохраняют прежние типы результата и не переключают режим выполнения.
