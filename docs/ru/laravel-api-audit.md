# Профиль Laravel Query Builder и контракты API 4.0

[English](../laravel-api-audit.md)

Каталог охватывает 299 публичных методов Laravel 11–13 и расширений драйвера, включая
вспомогательные методы и явно неподдерживаемые операции. Полный список находится в
[машиночитаемой матрице](../laravel-query-builder-api.json). Наличие метода в каталоге
не означает, что он есть во всех патчах Laravel: часть методов появилась позднее.
Статические средства регистрации макросов остаются механизмом самого Laravel.

## Профиль поддержки

| Семейство | Статус и границы |
| --- | --- |
| `select`, `addSelect`, `from`, сортировка, limit/offset | Поддерживаются в синтаксисе Manticore; псевдонимы таблиц допустимы для SELECT |
| `where`, `whereIn`, `whereIntegerInRaw`, BETWEEN, вложенные AND/OR, any/all/none | Поддерживаются сравнения с литералами; столбцы времени сравниваются с Unix timestamp |
| `whereNull`, `whereNotNull` | JSON и специальные проверки ID; применимость к другим атрибутам определяет сервер |
| `get`, `first`, `find`, `sole`, `value`, `pluck`, `implode`, exists-семейство | Адаптированы к PDO, преобразованиям типов и ограничениям результатов Manticore |
| `count`, `min`, `max`, `sum`, `avg`, GROUP BY и HAVING | Без DISTINCT; один HAVING типа Basic/Between/Raw. Вложенный HAVING и выполнение aggregate-методов с HAVING отклоняются |
| Пагинация, chunk/each/lazy, cursor | Поддерживаются с ограничениями ключей, счётчика, курсора и размера окна из [справочника](laravel-driver.md) |
| `whereFullText`, `whereJson*`, `search`, KNN, geo, facets, hybrid | Адаптированный API Manticore; дополнительные правила приведены ниже и в справочнике |
| `insert`, `insertGetId`, `replace`, `replaceGetId`, `update`, `delete`, `truncate` | Проверяются форма запроса и данные; неподходящие условия не отбрасываются молча |
| `updateOrInsert`, `replaceOrInsert`, `upsert` | Поиск перед записью, с описанными ниже гарантиями |
| Методы `*Raw`, `selectExpression`, `rawValue`, `fromRaw` | Явный SQL Manticore. Синтаксис и применимость выражения проверяет сервер; ошибки — QueryException |
| Callbacks, `when`, `unless`, `tap`, `pipe`, макросы и отладка | Механизмы Laravel; пользовательский callback/макрос определяет собственное поведение |
| `getBindings`, `getRawBindings`, клонирование, низкоуровневые bindings | Группы включают фактические параметры JSON/MATCH. Для объединения поисковых условий используйте вложенные запросы; ручное слияние отложенных параметров запрещено |

Следующие семейства явно отклоняются с LogicException при вызове либо перед выполнением SQL:

* JOIN и lateral JOIN, UNION, DISTINCT, блокировки, `groupLimit`, Laravel index hints.
* `whereLike` и LIKE/ILIKE/REGEXP в обычном `where`; binary и null-safe сравнения.
* `whereColumn`, BETWEEN по колонкам, сравнения кортежей, скалярные/IN/EXISTS-подзапросы,
  `selectSub`, `fromSub`. Нативные подзапросы Manticore имеют иной синтаксис.
* Фильтры дат и относительных дат Laravel. Для извлечения частей даты используйте нативное
  выражение SELECT с алиасом, для диапазона — явные Unix timestamp.
* `inOrderOf`, `inRandomOrder`, `explain`, `timeout($seconds)`. Для случайной сортировки есть
  явный `orderByRaw('RAND()')->option('rand_seed', 42)`; для лимита времени поиска —
  `option('max_query_time', $milliseconds)`. Это серверный лимит поиска, не сетевой таймаут PDO.
  `timeout(null)` только очищает настройку.
* `increment`, `decrement` и варианты Each: Manticore UPDATE не вычисляет такие выражения.
* `insertUsing`, `insertOrIgnore*`, `updateFrom` и векторные методы Laravel. Для векторов
  используйте `knn()` / `hybridSearch()`; строка не отправляется на генерацию embeddings автоматически.

На ранних патчах Laravel отсутствующий известный метод `where…` также отклоняется, вместо
превращения его имени в динамический фильтр по колонке. Обычный dynamicWhere сохраняется.
Регистрация пользовательского макроса остаётся явным выбором приложения.

## Правила записи

UPDATE/DELETE отклоняют проекции, агрегаты, DISTINCT, GROUP BY, HAVING, JOIN/UNION, сортировку,
limit/offset, блокировки, index hints, timeout и вычисляемые поисковые выражения. INSERT,
REPLACE и TRUNCATE дополнительно отклоняют WHERE. Записывать можно в одну физическую таблицу,
без псевдонима. Так, `groupBy(...)->delete()` и `where(...)->truncate()` завершаются исключением.

Строки пакета INSERT/REPLACE обязаны иметь одинаковый набор колонок; порядок ключей может
отличаться. Неправильная форма пакета вызывает InvalidArgumentException до записи. Присваивания
`details->color` в массиве обновления запрещены: передавайте полный JSON-атрибут. Изменение ID
через UPDATE запрещено. TEXT и columnar-атрибуты требуют REPLACE, даже при отключённых cast.

`insert([])` / `replace([])` возвращают true, `upsert([], ...)` — 0: это операции без SQL,
без проверки остальных аргументов upsert и без вызова before-query callback. `update([])` и
пустые/пакетные данные для `insertGetId` / `replaceGetId` вызывают InvalidArgumentException.

## Зафиксированные новые методы

[Снимок сигнатур](../query-builder-contracts.json) фиксирует имена параметров для named arguments,
типы, значения по умолчанию и тип результата 19 методов. Он проверяется на каждом поддерживаемом
major Laravel. Приведённые типы результатов относятся к штатному исполнению без пользовательской
подмены результата callback-функцией.

| Метод | Результат | Контракт |
| --- | --- | --- |
| `whereFullText($columns, $value, array $options = [], $boolean = 'and')` | Тот же билдер | Поле или непустой список простых имён; непустая строка. Единственная опция `escape` — bool, по умолчанию true. Неизвестные ключи перечисляются в исключении |
| `orWhereFullText($columns, $value, array $options = [])` | Тот же билдер | OR между текстовыми условиями; TEXT/атрибутный OR и отрицание текстовой группы запрещены |
| `whereJsonContains($column, $value, $boolean = 'and', $not = false)` | Тот же билдер | Массив содержит все искомые значения; отрицание означает отсутствие хотя бы одного |
| `whereJsonOverlaps($column, $value, $boolean = 'and', $not = false)` | Тот же билдер | Есть хотя бы один общий элемент; отрицание означает отсутствие всех |
| `whereJsonContainsKey($column, $boolean = 'and', $not = false)` | Тот же билдер | Значение пути отлично от null; JSON null и отсутствующий ключ не различаются |
| `whereJsonLength($column, $operator, $value = null, $boolean = 'and')` | Тот же билдер | Неотрицательная целая длина; два аргумента означают `=`. Отсутствующие пути/JSON null исключаются даже из поиска длины 0 |
| JSON-методы с `DoesntContain`, `DoesntOverlap`, `DoesntContainKey` и все `orWhereJson…` | Тот же билдер | Делегируют указанным выше проверкам с отрицанием/OR; включая недостающие алиасы раннего Laravel 11 |
| `updateOrInsert(array $attributes, array\|callable $values = [])` | bool | INSERT объединённых атрибутов/значений либо UPDATE переданных атрибутов найденного ID. Пустое обновление существующего документа — true |
| `replaceOrInsert(array $attributes, array\|callable $values = [])` | bool | INSERT либо полная замена найденного ID. Пропущенные поля сбрасываются, в том числе при пустом `$values` |
| `upsert(array $values, $uniqueBy, $update = null)` | int | Число обработанных строк. Для существующих документов REPLACE сохраняет необновляемые поля; для новых — INSERT. `$update = null` обновляет все переданные колонки, `[]` включает только INSERT |

JSON membership принимает строку, bool, конечное число или список таких значений. Null,
объекты, вложенные искомые массивы и пустой список contains отклоняются. Пустой overlaps не
находит ничего; отрицание находит всё. Действуют преобразования типов и LENGTH самого
Manticore — это не строгая JSON-типизация MySQL/PostgreSQL. Подробности и примеры:
[JSON](laravel-driver.md#json-фильтры), [полнотекстовые условия](laravel-driver.md#полнотекстовые-условия).

Повторные whereFullText объединяются в один MATCH. `match()` принимает одно нативное выражение
на верхнем уровне с AND; смешивать его с whereFullText нельзя. Для вложенных текстовых групп
есть whereFullText. Служебные JSON-алиасы отсутствуют в возвращаемых строках. `fetchUsing()`
применяется к get/cursor там, где доступен в Laravel; search, hybrid и методы поиска перед
записью требуют штатный объектный режим и отклоняют его замену, в том числе из beforeQuery.

Callback updateOrInsert/replaceOrInsert вызывается один раз с `$exists` и должен вернуть
ассоциативный массив. Поиск должен найти не более одного документа. Ключи — скалярные
физические атрибуты со значениями, отличными от null; ID 0 не является ключом поиска. ID существующего документа не
меняется. Upsert требует одинаковых колонок строк, наличия всех ключей `uniqueBy` и всех
обновляемых колонок. Повторяющиеся ключи и несколько строк с одним найденным ID запрещены.
TEXT без stored должен быть передан для обновления, поскольку его старое значение прочитать нельзя.

Upsert готовит все документы до первой записи и объединяет INSERT/REPLACE транзакцией.
Внешнюю транзакцию он не коммитит; ошибка исполнения откатывает её целиком, без savepoint.
Незакоммиченные записи Manticore не видны даже текущей транзакции. Изоляции поисков нет:
параллельный INSERT может дать конфликт, а параллельный REPLACE — потерю промежуточных изменений.
Ошибка COMMIT не приводит к повторной записи. UPDATE в updateOrInsert не откатывается.
См. [полный контракт записи](laravel-driver.md#обновление-или-вставка-замена-или-вставка-и-upsert).

## Ошибки и проверка профиля

| Ошибка | Значение |
| --- | --- |
| InvalidArgumentException | Неверное значение, путь, опция, форма пакета, ключ или результат callback |
| LogicException | Неподдерживаемый метод/сочетание условий, неоднозначный поиск, невозможность сохранить поле |
| TypeError | Нарушение объявленного PHP-типа аргумента, например не-array для options |
| Illuminate Database QueryException | Ошибка сервера/соединения, конфликт INSERT, неверный явный SQL или несовместимость со схемой |
| TransactionRollbackException | Ошибка операции и ошибка отката одновременно; обе причины доступны отдельно |

Схемозависимые проверки могут потребовать DESCRIBE. Явные несовместимые конструкции
отклоняются до выполнения запроса; raw SQL остаётся ответственностью вызывающего кода.
Пользовательские исключения из callbacks распространяются наружу.

`DatabaseDriverApiAuditTest` проверяет полноту каталога, сигнатуры и опасные комбинации.
`DatabaseDriverApiAuditIntegrationTest` проверяет данные на живом сервере, включая columnar,
невозможность потерять WHERE при TRUNCATE и выравнивание колонок пакета. Проверка
`php tests/check-api-contracts.php [autoload]` работает без Testbench. CI также устанавливает
минимальные компоненты Illuminate 11.0.0/12.0.0/13.0.0 без dev-зависимостей и выполняет живой smoke.
Полноценная совместимость с Eloquent и раздельными физическими read/write-серверами остаётся
отдельной областью проверки.
