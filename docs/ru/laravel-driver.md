# Драйвер Laravel Database

В ветке `dev-4.x` добавлен экспериментальный драйвер на стандартном Laravel Query Builder.
Его реализация работает с PDO напрямую и не вызывает самостоятельный PHP-билдер.
Старый API обёртки 3.x и зависимость от самостоятельного PHP-билдера удалены.

Перенос конфигурации и замены API для существующих приложений описаны в
[руководстве перехода с 3.x](upgrading-3.x-to-4.x.md).

## Конфигурация

Провайдер пакета автоматически регистрирует драйвер `manticore`. Добавьте именованное
соединение в массив `connections` файла `config/database.php` приложения:

```php
'manticore' => [
    'driver' => 'manticore',
    'host' => env('MANTICORE_HOST', '127.0.0.1'),
    'port' => env('MANTICORE_PORT', 9306),
    'username' => env('MANTICORE_USER'),
    'password' => env('MANTICORE_PASS'),
    'timeout' => env('MANTICORE_TIMEOUT', 5),
    'prefix' => '',
    'options' => [], // настройки PDO
],
```

Новый драйвер читает `database.connections` независимо от прежнего `config/manticore.php`.
Префиксы работают по правилам Laravel: `prefix => 'app_'` автоматически применяется к
`table('products')`. Плейсхолдер `?products` прежнего билдера не используется. Имя базы не требуется.

Отдельный `avadim\Manticore\Laravel\DatabaseServiceProvider` регистрирует только новый драйвер
как альтернативу автоматически обнаруживаемому `ServiceProvider`. Оба регистрируют один
нативный драйвер; достаточно одного провайдера.

## Запросы и результаты

```php
use Illuminate\Support\Facades\DB;

$connection = DB::connection('manticore');
$query = $connection->table('products')
    ->select('id', 'title', 'price')
    ->match('galaxy')
    ->where('price', '>', 100)
    ->option('max_matches', 2000)
    ->orderBy('id');

$rows = $query->limit(50)->get(); // Collection<stdClass>
$row = $connection->table('products')->find(1, ['id', 'title']); // stdClass|null
$rows = $connection->select('SELECT id FROM products WHERE price > ?', [100]); // array<stdClass>
```

`select()` на билдере только задаёт колонки и возвращает этот билдер. Сырые методы принимают
параметры Laravel: например, `whereRaw('price > ?', [100])` и
`selectRaw('price * ? as adjusted', [2])`. Доступны `toSql()`, `getBindings()` и `toRawSql()`.
`match()` передаёт полнотекстовое выражение Manticore как параметр; поисковые операторы
не экранируются как обычный текст.
Для обычного текста посетителя используйте `whereFullText()` с указанием полей либо
предварительно вызовите `ManticoreQueryBuilder::escapeMatch()` перед `match()`.

Соединение требует эмуляции подготовленных выражений PDO. На проверенном Manticore 28.6.6
серверные prepared UPDATE округляют дробные значения, поэтому отключение эмуляции отклоняется.
Конечные PHP float при выполнении передаются как проверенные числовые литералы; остальные
параметры остаются привязанными через PDO. SQL, параметры, события и исключения Laravel сохраняют
исходные значения. Это работает для позиционных и именованных параметров. INF и NAN отклоняются.

`option($name, $value)` принимает конечные числа, экранированные строки и карты положительных
целых весов для `field_weights` / `index_weights`. Повторная установка заменяет значение,
`option($name, null)` удаляет настройку. Названия ranker проверяются.

```php
$query->fieldWeights(['title' => 10, 'body' => 2])->ranker('bm25')->withScore();
$query->ranker('expr', 'sum(lcs*user_weight)*1000+bm25');
$query->option('comment', 'catalog search');
```

Для `expr` и `export` обязательна непустая формула; остальные встроенные ranker её не принимают.
Формулы экранируются как SQL-строки и выполняются движком выражений ранжирования Manticore.
Справочник: [поисковые настройки Manticore](https://manual.manticoresearch.com/Searching/Options).

`insert()`, `insertGetId()`, `update()` атрибутов и `delete()` используют выполнение запросов
и обработку ошибок Laravel. Ошибки SQL, включая отказ записи, бросают
`Illuminate\Database\QueryException`. События соединения, `DB::listen()`, журнал запросов
и `pretend()` проходят через стандартные механизмы Laravel.
`DB::disconnect()`, `DB::reconnect()` и `DB::purge()` управляют новым пулом соединений.
SQL автоматически не повторяется после ошибки соединения: потерянный ответ не доказывает,
что сервер не выполнил запись.

`lazy()`, `lazyById()` и `cursor()` возвращают `LazyCollection`. `cursor()` выполняет один SELECT,
а `lazy()` получает страницы. Буферизация PDO управляется настройками соединения;
ленивая коллекция сама по себе не гарантирует отсутствие буферизации результата.

## JSON-фильтры

В обычных фильтрах используйте пути Laravel через `->`. Поддерживаются вложенные ключи и
индексы с нуля: `details->dimensions->width`, `details->tags[0]` и `details->tags->0`.
Для ключа с точкой используйте кавычки: `details->"odd.key"`. Пути проверяются, ключи
экранируются для SQL, значения передаются параметрами. Wildcard и отрицательные индексы
отклоняются.

```php
$rows = $connection->table('products')->where('details->color', 'red')
    ->where('details->dimensions->width', '>', 100)
    ->whereIn('details->tags[0]', ['sale', 'new'])->get();
```

Следующие методы возвращают билдер. У каждого есть вариант `orWhereJson...`.

| Метод | Значение в этом драйвере |
| --- | --- |
| `whereJsonContains($column, $value)` | JSON-массив содержит все переданные значения |
| `whereJsonDoesntContain($column, $value)` | Отрицание contains: хотя бы одно значение отсутствует |
| `whereJsonOverlaps($column, $value)` | JSON-массив содержит хотя бы одно переданное значение |
| `whereJsonDoesntOverlap($column, $value)` | Ни одно переданное значение не входит в JSON-массив |
| `whereJsonContainsKey($column)` | По указанному пути есть значение, отличное от null |
| `whereJsonDoesntContainKey($column)` | Путь отсутствует либо содержит JSON null |
| `whereJsonLength($column, $operator, $value)` | Сравнение нативного LENGTH для значения, отличного от null; два аргумента означают равенство |

```php
$rows = $connection->table('products')->whereJsonContains('details->tags', 'sale')->get();
$rows = $connection->table('products')->whereJsonContains('details->tags', ['sale', 'new'])->get();
$rows = $connection->table('products')->where(function ($query) {
    $query->whereJsonOverlaps('details->tags', ['sale', 'new'])
        ->orWhereJsonLength('details->tags', 0);
})->whereJsonContainsKey('details->dimensions->width')->get();
```

Contains/overlaps принимают скаляр или список строк, boolean и конечных чисел.
Пустой список для contains, null, объекты и вложенные массивы в искомых значениях вызывают
InvalidArgumentException. Пустой список overlaps не находит ничего; его отрицание находит
всё. Эти методы проверяют элементы JSON-массива, а не вхождение объектов или рекурсивный
поиск. Сравнение следует нативным преобразованиям типов Manticore, включая числовые и boolean;
если различия типов важны, используйте однородные массивы. Отсутствующий путь или значение,
не являющееся массивом, не содержит искомых элементов и проходит отрицательные проверки.

**Семантика ключей и null отличается от драйверов MySQL/PostgreSQL в Laravel.** Manticore
не различает отсутствующий путь и JSON null. Поэтому `whereJsonContainsKey()` не включает
`{"key": null}`, но считает присутствующими ноль, false, пустую строку, пустой массив и пустой
объект. `whereNull('details->key')` находит и отсутствующий путь, и JSON null. Если приложению
нужно различать эти состояния, сохраняйте наличие ключа в отдельном атрибуте.

Длина должна быть неотрицательным целым числом; допустимые операторы: `=`, `!=`, `<>`, `<`,
`<=`, `>`, `>=`. Отсутствующие пути и JSON null исключаются, в том числе при поиске длины 0.
Нативный LENGTH считает элементы массива и поля объекта; для скаляров действуют правила
Manticore: длина числа равна 1, JSON-строки и boolean — 0. Это не универсальные правила
длины JSON для всех СУБД.

Contains/overlaps и длина используют вычисляемые выражения в SELECT с привязкой параметров.
Служебные алиасы удаляются из возвращаемых строк, включая результаты search и курсора.
Поддерживаются подсчёт, пагинация, полнотекстовые условия, KNN и гибридный поиск; общие
условия KNN/hybrid по-прежнему требуют AND. В UPDATE/DELETE такие вычисляемые фильтры
вызывают LogicException. Обычные JSON-пути и проверки ключей можно использовать для отбора
при записи. Синтаксис присваивания JSON-путям Laravel в массиве значений update не добавлен.
См. [функции массивов Manticore](https://manual.manticoresearch.com/Functions/Arrays_and_conditions_functions).

## Полнотекстовые условия

`whereFullText($columns, $value, array $options = [], $boolean = 'and')` сохраняет сигнатуру
Laravel и возвращает тот же билдер. Метод ограничивает поиск одним TEXT-полем или непустым
списком TEXT-полей. Имена должны быть простыми идентификаторами; SQL-выражения и `*`
отклоняются. Поля должны существовать в полнотекстовом индексе. Для примеров нужны TEXT-поля
`title` и `body`.

Начните с одного поля. Слова обрабатываются с учётом токенизации, морфологии и настроек
индекса Manticore. Это поиск по словам, а не SQL LIKE или поиск произвольной подстроки.

```php
$rows = $connection->table('products')->whereFullText('title', 'galaxy phone')->get();
$first = $connection->table('products')->whereFullText(['title', 'body'], 'galaxy')->first();
```

Повторные вызовы соединяются через AND и компилируются в один параметризованный MATCH.
Фильтры атрибутов можно добавлять до или после текстовых условий. `search()` возвращает
обычный SearchResult с метаданными.

```php
$result = $connection->table('products')->where('stock', '>', 0)
    ->whereFullText('title', 'galaxy')->whereFullText('body', 'phone')
    ->withScore()->orderByDesc('_score')->limit(20)->search();
```

Для альтернативных текстовых условий используйте `orWhereFullText()` внутри группы.
AND имеет приоритет над OR, как в Laravel; вложенные группы сохраняют смысл в MATCH.

```php
$rows = $connection->table('products')->where('stock', '>', 0)
    ->where(function ($query) {
        $query->whereFullText('title', 'phone')->orWhereFullText('body', 'tablet');
    })->get();
```

Единственная опция — `escape` (boolean, по умолчанию `true`). Поисковые операторы в тексте
посетителя экранируются; токенизация продолжает действовать. С `escape => false` значение
считается доверенным выражением Manticore внутри выбранных полей. В обоих режимах значение
передаётся как SQL-параметр. Выбор полей удобен для поиска, но не служит ограничением доступа.

```php
$rows = $connection->table('products')
    ->whereFullText('title', 'phone | tablet', ['escape' => false])->get();
```

Неизвестные опции, включая Laravel `mode`, `language` и `expanded`, вызывают
InvalidArgumentException с перечислением ключей. Пустой текст и некорректные имена полей
также отклоняются. Manticore не поддерживает OR между MATCH и атрибутами:
`whereFullText(...)->orWhere('stock', 1)` вызывает LogicException. То же относится к смешанным
вложенным OR-группам и отрицанию текстовых групп. В одном запросе нельзя смешивать `match()`
с `whereFullText()`; для полного нативного выражения используйте `match()` отдельно.
Не добавляйте эти условия перед `hybridSearch()` / `hybridGet()` / `hybridFirst()`: эти
терминальные методы принимают собственный текст. При сочетании с KNN требуется AND.
Полнотекстовые условия работают с пагинацией, курсором, UPDATE атрибутов и DELETE.

## Метаданные поиска

```php
$query = $connection->table('products')->match('galaxy')->withScore()->limit(20);
$result = $query->search(['id', 'title']);
$rows = $result->rows(); // Collection<stdClass>, включая колонку _score
$meta = $result->meta();

$meta->totalFound();  // int|null
$meta->total();       // int|null
$meta->time();        // float|null
$meta['total_found'];
$meta->toArray();
```

`search()` получает строки SELECT и SHOW META на одном PDO-соединении до вызова обработчиков
событий запросов. Снимок метаданных сохраняется после следующих команд и after-query callbacks.
`Meta` неизменяем, поддерживает перебор, подсчёт полей и JSON; отсутствующие поля возвращают
`null`. Чтение результата и его метаданных не выполняет дополнительных SQL-запросов.

SELECT и SHOW META попадают в события и журнал после получения снимка. Длительность SELECT
включает получение метаданных; SHOW META также имеет отдельную запись времени.
В `pretend()` служебный запрос не выполняется.

Обычный `get()` возвращает стандартную коллекцию без SHOW META; первый вызов может загрузить DESCRIBE.
Для отдельного чтения `$query->getMeta()` или `$connection->getMeta()` выполняет SHOW META
текущей сессии. Следующая команда, в том числе из обработчика события, может заменить эти
метаданные; используйте `search()`, когда строки и метаданные нужно получить вместе.

## MVA и геопоиск

```php
$rows = $connection->table('products')
    ->whereMvaAny('categories', [2, 3]) // ANY(categories) IN (2, 3)
    ->whereMvaAll('categories', '>=', 1)
    ->get();

$rows = $connection->table('places')
    ->withDistance('lat', 'lon', 55.75, 37.6, 'km')
    ->select('id', 'title')
    ->whereGeoDistance('lat', 'lon', 55.75, 37.6, 10, 'km')
    ->orderByDistance('lat', 'lon', 55.75, 37.6, 'km')
    ->get(); // в строках есть _distance
```

MVA-методы принимают скалярные сравнения, наборы IN / NOT IN и диапазоны BETWEEN / NOT BETWEEN.
Два аргумента означают равенство для скаляра и IN для массива. `orWhereMvaAny()` и
`orWhereMvaAll()` доступны и во вложенных условиях Laravel. Значения должны быть целыми числами
или строками с десятичными целыми в диапазоне PHP int; строки преобразуются с проверкой точности.
Пустые наборы, недопустимые операторы и диапазоны без двух границ отклоняются.
ALL проверяет каждый элемент атрибута на соответствие условию, а не наличие всех переданных значений.

Координаты задаются в градусах, широта первой; единицы расстояния — `m`, `km` или `mi`.
Поддерживаются числовые атрибуты и JSON-пути вроде `location.lat`. Координаты и радиус проверяются
на допустимый диапазон и конечность. `withDistance()` сохраняет вычисляемую колонку после
последующего `select()` и принимает имя колонки последним аргументом. Конфликтующие и
зарезервированные имена отклоняются.

Фильтр и сортировка работают и без `withDistance()`: служебные вычисляемые колонки удаляются
из результатов, включая `search()` и курсоры. Вложенные геофильтры, агрегаты и пагинация получают
нужные выражения. `orderByDistance()` сохраняет ранее заданную сортировку.

## Векторный поиск KNN

Индексируемый вектор объявляется как `$table->floatVector('embedding', 3, 'l2')`. Размерность
должна быть положительной, метрика — `l2`, `cosine` или `ip`. Без размерности создаётся обычный
вектор без индекса. Для HNSW на сервере нужна библиотека KNN.

```php
$result = $connection->table('products')
    ->knn('embedding', [1.0, 0.0, 0.0], 20, ['ef' => 100])
    ->withKnnDistance()->select('id', 'title')
    ->match('galaxy')->where('stock', '>', 0)
    ->orderByKnnDistance()->search();
```

`knn()` устанавливает LIMIT равным k; последующий `limit()` может изменить число выдаваемых строк.
Используется совместимый синтаксис `KNN(field, k, vector, options)`. Выбор кандидатов выполняет
сервер; k не гарантирует ровно k строк после фильтрации или при наличии нескольких чанков.
Разрешён один KNN верхнего уровня с AND-фильтрами. OR, вложенный KNN и запись с KNN отклоняются.
Вектор — непустой список конечных чисел; несовпадение размерности диагностирует сервер.
Настройки: `ef`, `oversampling`, `rescore`, `early_termination`, `prefilter`; их доступность зависит
от версии сервера. `withKnnDistance()` добавляет `_knn_distance` или заданный псевдоним,
`orderByKnnDistance()` сортирует по служебной колонке, которая удаляется из результата.
Справочник: [KNN в Manticore](https://manual.manticoresearch.com/Searching/KNN).

## Фасеты и подсветка

```php
$result = $connection->table('products')->match('galaxy')->limit(20)
    ->withHighlight('title', ['before_match' => '<em>', 'after_match' => '</em>'])
    ->facet('category', 'categories', 10, 'count', 'desc')
    ->facet('details.brand', 'brands', 20, 'value', 'asc')
    ->search(['id', 'title']);

$result->rows()[0]->_highlight; // строка с подсветкой
$result->facet('categories'); // Collection<stdClass>, колонки categories и count(*)
$result->facets(); // массив по именам фасетов
```

`facet(column, alias, limit, sort, direction)` принимает атрибут, MVA или JSON-путь, необязательный
уникальный псевдоним, положительный лимит бакетов, сортировку `count` / `value` и `asc` / `desc`.
Фильтры основного запроса действуют и на фасеты; лимит строк не ограничивает их счётчики.
Бакеты и метаданные сохраняются до вызова обработчиков событий. MVA-бакеты содержат отдельные
значения, счётчики — целые числа. Значения JSON-путей сохраняют типы PDO. Неизвестное имя фасета
вызывает `OutOfBoundsException`. Фасеты требуют `search()`: `get()`, курсоры, подсчёт для пагинации,
агрегаты, основной GROUP BY/HAVING и запись с фасетами отклоняются. Сырые выражения фасетов,
distinct-счётчики и отдельные фильтры каждого фасета пока не представлены в этом API.

`withHighlight(fields, options, query, alias)` принимает имя поля, список полей или пустой список
для всех сохранённых полей. По умолчанию добавляет `_highlight`, сохраняется после `select()`
и работает в `get()`, `search()` и курсорах. Без отдельного поискового выражения используется MATCH
основного запроса. Настройки и альтернативный запрос экранируются. Результат — строка с разделителями
полей и фрагментов Manticore; исходные поля должны храниться на сервере. Для вывода HTML приложение
само выбирает подходящие маркеры, настройки удаления HTML и обработку исходного содержимого.
Справочники: [фасеты](https://manual.manticoresearch.com/Searching/Faceted_search),
[подсветка](https://manual.manticoresearch.com/Searching/Highlighting).

## CALL-методы и автодополнение

```php
$keywords = $connection->keywords('gal*', 'products', ['stats' => 1]);
$suggestions = $connection->suggest('galaxi', 'products');
$lastWord = $connection->qsuggest('a galaxi', 'products');
$snippets = $connection->snippets(['galaxy phone', 'galaxy tablet'], 'products', 'galaxy');
$completions = $connection->autocomplete('gal', 'products', ['fuzziness' => 0]);

// Все наборы строк, включая пустые, как array<Collection<stdClass>>:
$sets = $connection->call('KEYWORDS', ['galaxy', 'products'], ['stats' => 1]);
```

Именованные методы возвращают первый набор строк как коллекцию и добавляют префикс соединения
к имени таблицы. Универсальный `call()` принимает позиционные скалярные аргументы и непустые
плоские списки; именованные настройки передаются как параметры `value AS name`. Он использует
аргументы в точности как переданы, без добавления префикса. Все наборы читаются, а курсор
закрывается до событий запросов. Типы результата соответствуют PDO. Работают журнал запросов,
`pretend()` и `QueryException` Laravel. Ошибки не вызывают автоматический повтор или подмену
ответа пустой коллекцией.

KEYWORDS, SUGGEST, QSUGGEST и SNIPPETS работают без Buddy. Для AUTOCOMPLETE нужны Buddy и
`min_infix_len` у таблицы, например `$table->setting('min_infix_len', 2)`. Если условия не выполнены,
метод передаёт ошибку сервера. Справочник:
[автодополнение Manticore](https://manual.manticoresearch.com/Searching/Autocomplete).
Локальные нативные тесты работают без Buddy; `MANTICORE_TEST_BUDDY=1` включает обязательную
проверку автодополнения. В CI этот флаг установлен, ошибка Buddy завершит проверку с ошибкой.

## Глубокие страницы

`paginate()` и `simplePaginate()` возвращают пагинаторы Laravel. Если окно SELECT превышает
стандартные 1000 совпадений, драйвер автоматически добавляет `max_matches = offset + limit`,
пока `max_matches` не задан явно. Это работает и для `lazy()` и других обходов со смещением.
Компиляция не меняет настройки исходного запроса. Явно заданное меньшее окно по-прежнему может
вызвать ошибку сервера; для больших обходов по ID используйте `chunkById()` или `lazyById()`.
Ограничения сервера действуют и для SELECT без явного `limit()`.

## Запись и транзакции

`insert()` принимает документ или пакет документов. `insertGetId()` и `replaceGetId()` получают
ID до вызова обработчиков событий, которые могут выполнить другую запись. `replace()` возвращает
boolean и заменяет документ целиком по ID: пропущенные поля сбрасываются к значениям сервера,
включая пустой MVA, JSON null и числовой ноль. Для изменения полнотекстовых полей используйте
REPLACE.

```php
$connection->table('products')->replace([
    'id' => 42, 'title' => 'Galaxy', 'price' => 199.5,
]);
$connection->transaction(function () use ($connection) {
    $connection->table('products')->replace(['id' => 42, 'title' => 'Galaxy', 'price' => 189.5]);
});
```

### Обновление или вставка, замена или вставка и upsert

`updateOrInsert($attributes, $values = [])` возвращает bool. Он ищет не более одного документа
по атрибутам поиска и существующим WHERE-условиям билдера. Если документа нет, вставляет
объединённые атрибуты и значения; если есть — обновляет только переданные атрибуты по ID.
Остальные поля сохраняются. Для существующего документа без новых значений возвращается true.
В ветви обновления действуют ограничения UPDATE; для изменения текста есть `replaceOrInsert()`.

```php
$connection->table('products')->updateOrInsert(['id' => 42], ['price' => 199.5]);
$connection->table('products')->updateOrInsert(['sku' => 'phone-42'], fn ($exists) => $exists
    ? ['price' => 189.5]
    : ['id' => 42, 'title' => 'Galaxy', 'price' => 199.5]);
```

`replaceOrInsert($attributes, $values = [])` также возвращает bool и принимает callback с
аргументом `$exists`. При отсутствии документа он выполняет INSERT, при наличии — полную
замену с сохранением найденного ID. В замену передаются объединённые атрибуты и значения,
без подмешивания старого документа: пропущенные поля сбрасываются, как в `replace()`.

```php
$connection->table('products')->replaceOrInsert(['id' => 42], [
    'title' => 'Galaxy phone', 'price' => 189.5, 'stock' => 10,
    // Передайте также остальные поля, которые должны сохраниться.
]);
```

`upsert($rows, $uniqueBy, $update = null)` возвращает число успешно обработанных входных строк:
по одной на строку, без специфичного для СУБД подсчёта затронутых записей. Принимается один
документ или список документов с одинаковым набором колонок. `uniqueBy` — имя колонки либо
непустой список колонок поиска; они должны быть в каждой строке. Это эмуляция из нескольких
запросов.

```php
$count = $connection->table('products')->upsert([
    ['id' => 42, 'title' => 'Galaxy phone', 'price' => 189.5],
    ['id' => 43, 'title' => 'Galaxy tablet', 'price' => 249.5],
], ['id'], ['title', 'price']);
```

Новые документы вставляются со всеми переданными значениями. Для существующего документа
драйвер читает сохранённые поля, накладывает только колонки из `$update` и выполняет REPLACE
полного документа с прежним ID. Так можно менять TEXT, JSON, MVA, векторы и columnar-атрибуты,
сохраняя остальные поля. JSON-объекты/массивы и 64-битные числа сохраняют представление,
в том числе при отключённых преобразованиях чтения. `$update = null` обновляет все переданные
колонки; пустой список включает только INSERT, при конфликте ID возникает ошибка вместо
замены. Пустой массив строк возвращает 0. Список обновления должен содержать имена колонок,
присутствующих в каждой строке; SQL-выражения в значениях и ассоциативные карты обновлений
отклоняются.

Все поиски и полные документы для замены готовятся до первой записи. INSERT/REPLACE выполняются
в одной транзакции с откатом при ошибках до COMMIT. Если внешняя транзакция уже открыта,
upsert присоединяется к ней и при успехе оставляет COMMIT вызывающему коду. Ошибка выполнения
откатывает её целиком, включая ранее подготовленные записи вызывающего кода: savepoint нет.
Ошибка COMMIT по-прежнему имеет неопределённый результат, автоматического повтора нет.
Manticore не видит собственные незакоммиченные записи: не разбивайте зависимые upsert на
несколько вызовов внутри внешней транзакции, передавайте их одним пакетом.

Транзакция даёт откат записей, **но не изоляцию поиска и обновления**. Параллельная вставка
может привести к конфликту, а замена — затереть изменения между чтением и записью. Для
произвольных атрибутов поиска сервер не обеспечивает уникальность: за неё отвечает приложение.
Предпочтителен `id`. Повторяющиеся ключи в пакете, несколько строк с одним найденным ID и
поиск, нашедший несколько документов, вызывают исключения. TEXT без флага stored невозможно
прочитать: при обновлении существующих документов такие поля должны быть и во входных данных,
и в списке обновления, иначе upsert выдаст ошибку вместо их молчаливого сброса.

Атрибуты поиска должны быть физическими скалярными колонками со значениями, отличными от null;
JSON-пути, TEXT, JSON, MVA и векторы как ключи поиска не поддерживаются. ID принимает целые
числа и строковые представления без преобразования во float; 0 нельзя использовать для поиска,
поскольку он означает генерацию ID. Изменять ID существующего документа нельзя. Все три метода
клонируют исходный билдер, читают через write-соединение и отклоняют проекции, сортировку,
limit/offset, группировки, фасеты, KNN, поисковые опции и after-query callbacks.
`updateOrInsert()` / `replaceOrInsert()` учитывают существующие WHERE при поиске;
`upsert()` отклоняет WHERE и берёт ключи поиска только из `uniqueBy`.

Поддерживается один уровень транзакций и after-commit callbacks Laravel. Вложенные транзакции,
DDL внутри транзакции и число попыток, отличное от одного, отклоняются. При сбое BEGIN, COMMIT
или ROLLBACK соединение с неопределённым состоянием отключается; SQL и callback транзакции
автоматически не повторяются. Если ошиблись и callback, и откат, `TransactionRollbackException`
сохраняет обе ошибки в `callbackError` и `rollbackError`. Ошибка получения ID возможна после
успешной записи и не приводит к повторному INSERT. UPDATE ограничен операциями над атрибутами,
которые поддерживает Manticore.

В транзакциях Manticore участвуют только INSERT, REPLACE и DELETE. UPDATE на месте не
откатывается; текущий драйвер не запрещает UPDATE внутри транзакции. Для изменений с откатом
используйте REPLACE полного документа, передавая все сохраняемые атрибуты.
См. [транзакции Manticore](https://manual.manticoresearch.com/Data_creation_and_modification/Transactions).

## Схема и миграции

```php
use avadim\Manticore\Laravel\Database\ManticoreBlueprint;
use Illuminate\Support\Facades\Schema;

Schema::connection('manticore')->create('products', function (ManticoreBlueprint $table) {
    $table->id(); // встроенный 64-битный ID документа Manticore
    $table->text('title'); // полнотекстовое поле
    $table->string('sku'); // строковый атрибут
    $table->float('price');
    $table->json('details');
    $table->multi('categories');
    $table->multi64('external_ids');
    $table->floatVector('embedding');
    $table->setting('min_word_len', 2);
});

$schema = Schema::connection('manticore');
$schema->hasTable('products');
$schema->getColumnListing('products');
$schema->table('products', fn (ManticoreBlueprint $table) => $table->integer('stock'));
$schema->dropIfExists('products');
```

Также доступны типы `integer`, `bigInteger`, `boolean` и `timestamp`. Длина строки и точность
float из объявления Laravel не создают SQL-ограничений; `float()` соответствует нативному float
Manticore. Для TEXT доступны флаги `stored()` и `indexed()`. Настройки CREATE экранируются.
ALTER поддерживает добавление и удаление колонок в порядке объявления. В `dev-4.x` после alpha.1
также доступны изменение настроек через `setting()`, чтение через `getSettings()`, расширение
построчного int до bigint через `change()` и переименование таблицы через `rename()` с Buddy.
Примеры, проверки и правила отката — в [расширенном Schema Builder](schema-alter.md).
Произвольное изменение типа, переименование колонок, nullable/default, внешние ключи,
обычные индексы Laravel и неподдерживаемые модификаторы отклоняются до выполнения DDL.

Используйте обычные миграции с `protected $connection = 'manticore'` и явным
`Schema::connection('manticore')`. Таблицу учёта миграций храните в основной SQL-базе приложения.
DDL не поддерживает транзакции: ошибка сервера посередине ALTER из нескольких команд оставляет
предыдущие изменения применёнными. Учитывайте это состояние в `down()` и при восстановлении.

## Преобразование атрибутов и кеш схемы

Гибридный поиск описан в [руководстве с пошаговыми примерами](hybrid-search.md).
[Проверка возможностей и замена индекса в режиме обслуживания](hybrid-and-index-replacement.md) описаны отдельно.

Перед первым чтением или записью Query Builder выполняет DESCRIBE и кеширует схему отдельно
для каждой таблицы и соединения. JSON-массивы и объекты сериализуются при записи и читаются
как ассоциативные массивы; JSON null сохраняется как null. MVA/MVA64 и векторы принимают
массивы-списки и возвращают массивы. Целые числа сохраняют точность: значения за пределами PHP int
возвращаются строками. Boolean читается как boolean, числовые атрибуты — как числа.
`DateTimeInterface` в timestamp преобразуется в секунды Unix. SQL Expressions передаются напрямую.

Преобразование работает в `get()`, `first()`, `pluck()`, `search()`, курсорах и ленивых коллекциях,
включая простые псевдонимы колонок. Типы вычисляемых выражений не определяются автоматически.
Сырой `$connection->select()` сохраняет типы PDO. Настройка соединения `cast_attributes => false`
отключает преобразование и связанную с ним загрузку схемы; структурированные значения нужно сериализовать вручную.
Описание схемы, курсорная пагинация и точный подсчёт групп по-прежнему проверяют типы колонок.

Schema Builder и сырые CREATE/ALTER/DROP/TRUNCATE/RENAME сбрасывают кеш, в том числе при ошибке.
Переподключение также очищает его. После внешнего DDL вызовите `$connection->forgetSchema('products')`
с логическим именем без префикса либо `$connection->forgetSchema()` для всех таблиц.
Загрузка схемы выполняется перед поисковым SELECT и не затирает снимок его метаданных.

## Обход больших результатов

Доступны методы Laravel `chunk()`, `each()`, `lazy()`, `chunkById()`, `eachById()`, `lazyById()`,
`chunkByIdDesc()` и `lazyByIdDesc()`. Обходы со смещением требуют явного стабильного `orderBy()`;
варианты ById сами сортируют по ID документа. Выбирайте колонку границы страницы, а при её
переименовании передавайте исходное имя и псевдоним:

```php
$connection->table('products')->select('id as document_id', 'title')
    ->lazyById(700, 'id', 'document_id')->each(function ($row) {
        // Обработка документа.
    });
```

Для удаления обработанных документов или изменения атрибутов фильтра используйте ById.
Не меняйте сам ID и объединяйте OR-условия в замыкании: условие следующего ID должно применяться
ко всему фильтру. Обход не создаёт снимка при параллельных вставках и изменениях.
`false` из callback chunk/each останавливает следующие страницы. Ленивые коллекции выполняют
запросы при переборе, `take()` прекращает загрузку следующих страниц. Преобразование JSON/MVA
сохраняется. Как в Laravel, некоторые методы со смещением меняют билдер; клонируйте запрос перед
повторным использованием. Для offset-обходов растёт `max_matches`, варианты ById избегают роста смещения.

## Жизненный цикл курсора и буферизация

`cursor()` откладывает выполнение до перебора и выполняет один SELECT. Курсор PDO закрывается
после полного чтения, ошибки fetch или уничтожения остановленного итератора. `take(1)`, обычный
`break` и исключение в callback коллекции освобождают временные итераторы. Если сохраняете сам
итератор, при раннем выходе удалите все ссылки на него в `finally`:

```php
$iterator = $connection->table('products')->orderBy('id')->limit(5000)->cursor()->getIterator();
try {
    foreach ($iterator as $row) {
        // Обработка документов; допустим ранний break.
    }
} finally {
    unset($iterator);
}
```

По умолчанию PDO буферизует результат MySQL, позволяя другие запросы во время перебора.
Настройка `options => [PDO::MYSQL_ATTR_USE_BUFFERED_QUERY => false]` отключает буферизацию.
Пока такой итератор активен, для остальных SQL используйте отдельное соединение, в том числе
в обработчиках событий и callback. PDO отвергает параллельный SQL на занятом соединении ошибкой
2014; драйвер передаёт `QueryException` и не отбрасывает непрочитанный результат молча.
После завершения перебора или освобождения итератора соединение снова работает. Ошибки fetch
сохраняют исходные SQL и параметры. В `pretend()` возвращается пустой курсор без подключения.

Курсор выполняет один запрос, ограниченный окном выдачи Manticore. Задайте явный лимит
с автоматическим повышением `max_matches` либо используйте `lazyById()` для постраничного обхода
всей таблицы. Потоковый перебор в PHP сам по себе не отключает буферизацию и не создаёт снимок данных.

## Курсорная пагинация и подсчёт

`cursorPaginate()` возвращает `CursorPaginator` Laravel с закодированными курсорами вперёд/назад
и условиями WHERE по границе страницы вместо растущего смещения. Запрос подсчёта не выполняется.
По умолчанию сортировка идёт по ID. Другие ключи — выбранные целочисленные атрибуты, boolean, timestamp или их
простые псевдонимы; при необходимости в конец сортировки добавляется ID для однозначного порядка.
Выбирайте все колонки сортировки, включая ID. Float, строки, JSON/MVA, вычисляемые ключи, сырые SELECT,
смещение, группировки, фасеты и KNN этот метод отвергает.

```php
$query = $connection->table('products')->select('id', 'stock', 'title')->orderBy('stock');
$first = $query->cursorPaginate(50);
$next = $query->cursorPaginate(50, ['*'], 'cursor', $first->nextCursor()?->encode());
$previous = $query->cursorPaginate(50, ['*'], 'cursor', $next->previousCursor());
```

Manticore может округлять float в SQL-выдаче: например, 0.000000142857142857 становится 0.00000014.
Поэтому float не даёт точной границы курсора; используйте целочисленные ключи или offset-пагинацию.
Размер страницы должен быть положительным целым числом. Некорректные токены, отсутствующие/null
или дробные границы и целые за пределами PHP int отклоняются. ID больше 2^53 сохраняют
точность на 64-битном PHP. Используйте с токеном те же фильтры и сортировку: курсор не создаёт
снимка при параллельных изменениях. Исходный запрос клонируется перед пагинацией.

Для документов `paginate()` выполняет обычный COUNT. Для GROUP BY по одному или нескольким
скалярным атрибутам подсчёт берётся из снимка SHOW META сгруппированного запроса с учётом HAVING.
Служебный COUNT сначала ограничивает число групп количеством подходящих документов; клоны
пагинации используют этот `max_matches` и `accurate_aggregation=1` для подсчёта и выдачи.
Это обходит неподдерживаемый COUNT над подзапросом Laravel и предотвращает усечение групп
стандартным окном 1000. Исходные настройки и параметры сохраняются. Для групп нужны прямые имена
скалярных атрибутов; MVA/JSON, сырые выражения группировки и HAVING без GROUP BY отклоняются.
Manticore принимает одно условие HAVING; несколько условий явно отклоняются драйвером.
Большое число групп может потребовать значительного объёма памяти сервера; для обхода документов
используйте курсорную пагинацию по ID.

Точный подсчёт для пагинации отклоняет KNN, фасеты и ненулевой cutoff. Для них используйте
`search()` с поисковыми метаданными либо `simplePaginate()`, если запрос его поддерживает и общий
счётчик не нужен. `total_found` обычного поиска может быть оценкой и не подменяет COUNT документов.
Справочники: [пагинация Laravel](https://laravel.com/docs/13.x/pagination#cursor-pagination),
[группировка Manticore](https://manual.manticoresearch.com/Searching/Grouping).

## Текущие ограничения

Полный список методов — в [аудите API и зафиксированных контрактах](laravel-api-audit.md).
Неподдерживаемые фильтры дат/LIKE/сравнения колонок/подзапросы, index hints, случайная/CASE-сортировка
и арифметические UPDATE-методы явно отклоняются. Записи отклоняют неприменимые условия;
INSERT/REPLACE/TRUNCATE запрещают WHERE, пакеты INSERT/REPLACE требуют одинаковых колонок.
Присваивания JSON-путям не поддерживаются. getRawBindings() включает фактические параметры MATCH/JSON.

Минимальная поддерживаемая версия — Manticore 28.6.6. CI проверяет закреплённый официальный
образ и `latest` с комплектными Buddy/KNN. Это граница поддержки, а не утверждение, что все
старые серверы несовместимы. См. [политику совместимости](testing.md#совместимость-с-сервером).

- JOIN, UNION, SELECT DISTINCT, блокировки и group limits пока отклоняются драйвером.
  Также отклоняются подзапросы WHERE EXISTS и агрегаты с HAVING.
- UPDATE и DELETE отклоняют сортировку, лимит, смещение, JOIN, поисковые настройки и вычисляемые выражения поиска,
  чтобы не игнорировать их молча. Обновлению полнотекстовых полей нужна отдельная обработка.
- Нативное изолированное/атомарное разрешение конфликтов `upsert()` не поддерживается;
  эмуляция объединяет записи транзакцией. Расширенные настройки фасетов
  пока не представлены отдельными методами.
- Разделение чтения и записи и совместимость с Eloquent пока не подтверждены.

Старый API `ManticoreDb`, `Manager`, `Connection`, `Query`, `Row` и `Factory` удалён.
Замены вызовов и типов приложения описаны в [руководстве перехода](upgrading-3.x-to-4.x.md).
