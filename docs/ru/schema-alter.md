# Расширенный Schema Builder

[English](../schema-alter.md)

Доступен в **4.0.0** для real-time таблиц в RT-режиме.
Поддерживаемый минимум — Manticore 28.6.6.

## Изменение настроек таблицы

```php
use Illuminate\Support\Facades\Schema;

$schema = Schema::connection('manticore');
$schema->table('products', function ($table) {
    $table->setting('min_infix_len', 3);
    $table->setting('morphology', 'stem_en');
});
$settings = $schema->getSettings('products'); // array<string, string>
```

Соседние настройки объединяются в один ALTER с присваиваниями через пробел.
ADD/DROP/change разделяют группы настроек; порядок объявления сохраняется.
Для повторного имени в одной группе используется последнее значение. CREATE также использует `setting()`.

| Настройка ALTER | Допустимый ввод |
| --- | --- |
| `min_prefix_len`, `min_infix_len`, `min_word_len` | Неотрицательное целое число либо строка из цифр |
| `expand_keywords`, `index_exact_words`, `html_strip` | `0`, `1`, `'0'`, `'1'` |
| `dict` | `'keywords'` либо `'crc'` |
| `rt_mem_limit` | Положительное целое число байтов либо строка из цифр с необязательным суффиксом K/M/G |
| `morphology`, `charset_table`, `stopwords`, `prefix_fields` | Однострочная строка |

Имена и формат значений проверяются до выполнения DDL. Диапазоны, сочетания настроек,
наличие словарей и файлов проверяет сервер. Неподдерживаемая настройка ALTER вызывает
`LogicException`, некорректное значение — `InvalidArgumentException`. Остальные поддерживаемые
настройки CREATE остаются доступны при CREATE. Многострочные значения отклоняются.

`getSettings()` при каждом вызове выполняет SHOW TABLE SETTINGS через соединение записи.
Он возвращает только выданные сервером настройки, не подставляя пропущенные значения по умолчанию.
Значения — строки в серверном формате: например, `32M` превращается в `'33554432'`.
Это не полный конфиг и не точная копия параметров CREATE; перед сравнением в инструменте
синхронизации нормализуйте желаемые значения. Неожиданный формат или повторяющиеся имена
вызывают `UnexpectedValueException`, чтобы не возвращать неоднозначный результат.

Изменение полнотекстовых настроек не перестраивает существующие документы.
Для применения новых правил к существующему индексу явно выполните переимпорт или переиндексацию.

## Расширение целочисленного атрибута

```php
Schema::connection('manticore')->table('products', function ($table) {
    $table->bigInteger('stock')->change();
});
```

Поддерживается только расширение существующего атрибута `int` с построчным хранением
(DESCRIBE показывает его как `uint`) до знакового `bigint`. Значения сохраняются,
после изменения колонка принимает 64-битные целые числа. Исходный bigint, columnar-атрибут,
ID, отсутствующая колонка, сужение и другие преобразования отклоняются.
Автоматического пересоздания таблицы или копирования данных нет.

Перед первой командой `change()` обновляет DESCRIBE и проверяет исходный тип с учётом
предшествующих ADD/DROP в том же Blueprint. `toSql()` и `pretend()` работают без соединения:
проверяют целевое определение, но не читают исходную таблицу. Одновременный внешний DDL
может привести к ошибке сервера уже после проверки.

Обратное преобразование автоматически не выполняется. Не используйте `integer()->change()`
в `down()`: оставьте расширенный тип, объявите миграцию необратимой либо реализуйте отдельно
проверенное пересоздание с контролем данных. Драйвер не выбирает такое пересоздание за приложение.

## Переименование таблицы

```php
Schema::connection('manticore')->rename('products', 'catalog');
```

Требует Buddy. Оба имени логические, без префикса соединения; драйвер добавляет префикс
к каждому. Переименование должно занимать отдельный Blueprint. Пустое имя, квалифицированное
имя, псевдоним и совпадение с исходным именем отклоняются. Существующая таблица не перезаписывается.
Отсутствие Buddy, исходной таблицы или конфликт имён приводит к серверному `QueryException`.
Переименование колонок не поддерживается.

## Ошибки и восстановление миграций

Определения компилируются и проверяются до первой команды DDL. ALTER и RENAME очищают
кеш схемы соединения перед выполнением и в `finally`, в том числе при ошибке.
`change()` дополнительно обновляет исходную схему до выполнения команд. Другие соединения
и процессы сохраняют собственные кеши; после внешнего DDL вызовите `forgetSchema()` либо перезапустите их.

DDL не выполняется внутри транзакции драйвера и не является атомарным. Ошибка поздней команды
оставляет предыдущие изменения колонок и настроек применёнными. Перед повтором или восстановлением
проверьте фактическую схему и настройки. Возврат полнотекстовой настройки к старому значению
не переиндексирует документы, записанные во время действия новой настройки.

Таблицу учёта миграций храните в основной SQL-базе и явно выбирайте Manticore внутри миграций.
Тестовые миграции в `tests/fixtures/driver-alter-migrations` репозитория показывают применение и откат
с сохранением документов и расширенного типа bigint.
