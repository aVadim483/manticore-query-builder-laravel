# Гибридный поиск

[English](../hybrid-search.md)

Гибридный поиск объединяет документы, найденные по словам, с документами, найденными
по близости векторов. Документ может попасть в результат через любую из двух ветвей.
В этой библиотеке Manticore выполняет два отдельных запроса, а PHP объединяет выдачи
по ID и рассчитывает их порядок через weighted RRF.

Руководство описывает **4.0.0-alpha.3**. В alpha.2 вместо выполняющих методов использовался
вызов `hybrid(...)->search()`; переход описан в конце документа.

## 1. Самый простой поиск

В примерах используется таблица `products`: в ней есть полнотекстовые поля `title`/`body`
и векторная колонка `embedding` с HNSW-индексом на 3 измерения. Как создать учебную таблицу,
показано ниже. Соединение `manticore` должно быть настроено в `config/database.php`.

<!-- example: minimal -->
```php
use Illuminate\Support\Facades\DB;

$vector = [1, 0, 0];
$products = DB::connection('manticore')->table('products')
    ->hybridGet('телефон', 'embedding', $vector);
```

`$products` — обычная `Collection<stdClass>`, как у `get()`. Документы уже расположены
в порядке итогового ранжирования. Дополнительно вызывать `get()` или `search()` не нужно.

Три аргумента означают:

| Аргумент | Назначение |
| --- | --- |
| `'телефон'` | Текст для полнотекстового поиска |
| `'embedding'` | Имя векторной колонки в Manticore, не имя текстового поля |
| `$vector` | Вектор запроса той же размерности, что и колонка |

Трёхмерный вектор здесь условный, для учебной таблицы. В приложении получайте embeddings
документов и запросов одной совместимой моделью. Библиотека не преобразует текст в вектор.

Без опций используются равные веса ветвей, константа RRF 60 и до 100 кандидатов
от каждой ветви. Повторяющиеся ID объединяются.

## 2. Только лучший документ

<!-- example: first -->
```php
$product = DB::connection('manticore')->table('products')
    ->hybridFirst('телефон', 'embedding', $vector);
```

Возвращается `stdClass` либо `null`, как у `first()`. Сначала ранжируются полные окна
кандидатов обеих ветвей, затем выбирается лучший документ. Лимиты ветвей до 1 не уменьшаются:
иначе можно потерять документ, который высоко расположен в обеих выдачах.

## 3. Одинаковые фильтры для обеих ветвей

<!-- example: filters -->
```php
$products = DB::connection('manticore')->table('products')
    ->where('stock', '>', 0)
    ->where('brand', 'acme')
    ->whereIn('category_id', [1, 2])
    ->hybridGet('телефон', 'embedding', $vector);
```

Фильтры применяются к текстовой и векторной ветвям до объединения. Условия задаются
перед выполняющим методом. `hybridGet()` уже вернул коллекцию: добавлять к ней SQL-условия поздно.

## 4. Изменение веса одной ветви

Четвёртый аргумент необязателен. Начните с одной настройки, если нужно изменить баланс:

<!-- example: weights -->
```php
$products = DB::connection('manticore')->table('products')
    ->hybridGet('телефон', 'embedding', $vector, [
        'vector_weight' => 2,
    ]);
```

Текстовый вес остаётся равным 1, векторный становится 2. Это увеличивает вклад позиции
в векторной выдаче; сырые значения WEIGHT и расстояния между собой не складываются.
Нулевой вес отключает соответствующую ветвь. Хотя бы один вес должен быть положительным.

## 5. Оценки, ранги и метаданные

Для подробного результата используйте `hybridSearch()`:

<!-- example: result -->
```php
$result = DB::connection('manticore')->table('products')
    ->hybridSearch('телефон', 'embedding', $vector);

$documents = $result->rows();
$hits = $result->hits();
$bestHit = $hits->first();
$textMeta = $result->textMeta;
$vectorMeta = $result->vectorMeta;
$totals = $result->totals();
```

| Метод | Результат |
| --- | --- |
| `hybridSearch(...)` | `HybridResult`: документы, оценки, метаданные и пагинация окна |
| `hybridGet(...)` | `Collection<stdClass>`: только документы |
| `hybridFirst(...)` | `stdClass|null`: только лучший документ |

Все три метода выполняют запросы сразу. В `HybridHit` доступны `id`, `document`, итоговый
`score`, `textRank`, `vectorRank`, `textScore` и `distance`. Поля отсутствующей ветви — `null`;
её вклад в итоговую оценку равен нулю. Ранги начинаются с 1.

Формула: `text_weight/(rank_constant+text_rank) + vector_weight/(rank_constant+vector_rank)`.
Если документ присутствует в обеих ветвях, его поля берутся из текстовой. При равной оценке
используется возрастающий числовой порядок ID с сохранением точности bigint.

## 6. Пагинация ограниченного окна

<!-- example: page -->
```php
$result = DB::connection('manticore')->table('products')
    ->hybridSearch('телефон', 'embedding', $vector, [
        'text_candidates' => 200,
        'vector_candidates' => 200,
    ]);

$page = $result->paginateWindow(perPage: 20, page: 2);
$windowCount = $result->windowTotal();
$globalCount = $result->totalFound(); // null
```

Это пагинация объединённого окна кандидатов, а не всей таблицы. До удаления дублей
в примере может быть до 400 документов. В paginator находятся `HybridHit`; документ — в `document`.
Переход по страницам уже полученного `$result` не выполняет новые SQL-запросы.

`windowTotal()` точен для полученного окна; полный total объединения неизвестен.
`totals()` помечает окно как `exact`, общий total как `unavailable`, totals ветвей как
`unknown` либо `unavailable` для отсутствующей ветви. Суммировать totals ветвей нельзя:
они пересекаются, ограничены настройками сервера, а KNN может быть приближённым.
RAM KNN иногда сообщает больше совпадений, чем возвращает top-k.

Для глубоких страниц нужно заранее увеличить окна кандидатов. Это увеличивает работу,
память и трафик. Новый поиск после изменения данных может дать другой порядок.
Неограниченного обхода через cursor для этого API нет.

## 7. Расширенный пример: фильтры, текстовые веса и KNN

Используйте этот вариант, когда уже понятны настройки выше. Значения ниже иллюстрируют API,
а не являются универсальной настройкой качества или скорости для любого индекса.

<!-- example: advanced -->
```php
$result = DB::connection('manticore')->table('products')
    ->where('stock', '>', 0)
    ->where('brand', 'acme')
    ->where(function ($query) {
        $query->whereIn('category_id', [1, 2])
            ->whereBetween('price', [100, 1000]);
    })
    ->whereMvaAny('tags', [1, 2])
    ->fieldWeights(['title' => 10, 'body' => 2])
    ->ranker('bm25')
    ->option('max_matches', 1000)
    ->hybridSearch('телефон', 'embedding', $vector, [
        'text_weight' => 1.5,
        'vector_weight' => 0.75,
        'rank_constant' => 60,
        'text_candidates' => 300,
        'vector_candidates' => 150,
        'escape' => true,
        'knn_options' => [
            'ef' => 300,
            'oversampling' => 2,
            'prefilter' => true,
            'rescore' => true,
            'early_termination' => false,
        ],
    ]);
```

`fieldWeights()` влияет на ранжирование текстовых кандидатов. Веса `text_weight` и
`vector_weight` управляют уже объединением ветвей — это разные уровни настройки.
`knn_options` передаются серверному KNN; они не управляют PHP-слиянием.

## 8. Расширенный синтаксис MATCH

По умолчанию текст экранируется как буквальный ввод. Чтобы намеренно использовать
операторы и выбор текстовых полей, отключите экранирование:

<!-- example: syntax -->
```php
$result = DB::connection('manticore')->table('products')
    ->hybridSearch('@title телефон | @body поездка', 'embedding', $vector, [
        'escape' => false,
    ]);
```

Это меняет только текстовую ветвь. Вектор по-прежнему передаётся отдельно.

## Справочник опций

| Опция | По умолчанию | Допустимые значения / назначение |
| --- | --- | --- |
| `text_weight` | 1 | Конечное число 0..1000000, вклад текстового ранга |
| `vector_weight` | 1 | Конечное число 0..1000000, вклад векторного ранга |
| `rank_constant` | 60 | Целое 0..1000000; большая константа сглаживает различия вкладов соседних рангов |
| `text_candidates` | 100 | Целое 1..10000, максимум текстовых кандидатов |
| `vector_candidates` | 100 | Целое 1..10000, число запрашиваемых KNN-кандидатов |
| `escape` | true | Экранировать текст MATCH; пустой текст пропускает текстовую ветвь |
| `knn_options` | [] | `ef` — положительное целое; `oversampling` — конечное число ≥1; `prefilter`, `rescore`, `early_termination` — bool либо 0/1 |

Обрезка окна, HNSW и фильтрация могут уменьшить число возвращённых кандидатов.
Размерность вектора и метрика проверяются по объявлению HNSW. Для cosine нужен ненулевой вектор.

## Учебная схема

Требуются Manticore 28.6.6+ и библиотека KNN. Таблицу создавайте миграцией; генерация
embeddings и загрузка документов остаются приложению. Для примеров выше схема такая:

<!-- example: schema -->
```php
use Illuminate\Support\Facades\Schema;

Schema::connection('manticore')->create('products', function ($table) {
    $table->text('title');
    $table->text('body');
    $table->string('brand');
    $table->integer('stock');
    $table->integer('category_id');
    $table->float('price');
    $table->multi('tags');
    $table->floatVector('embedding', 3, 'l2');
});
```

## Выполнение, ошибки и ограничения

Ветви выполняются последовательно через один write PDO без общего транзакционного снимка.
Их метаданные захватываются до следующего запроса или query listener. Пустая ветвь не мешает
вернуть документы другой. Ошибка ветви выходит наружу, не превращаясь в пустую успешную выдачу;
автоматической подмены режима нет. Проверка возможностей сервера описана
[отдельно](hybrid-and-index-replacement.md).

Общий запрос допускает простое логическое имя таблицы и атрибутные AND-условия, включая
вложенные AND/MVA и [JSON-фильтры](laravel-driver.md#json-фильтры). Служебные выражения
JSON-фильтров копируются в обе ветви. Проекции, raw-условия/выражения, MATCH/KNN, фасеты, собственная сортировка,
limit/offset, joins, группировки, callbacks и серверные настройки fusion отклоняются.
Билдер-источник не меняется. Внутренние имена колонок `__hybrid_text_score` и
`__hybrid_distance` зарезервированы. Прикладные поля не перезаписываются оценками.

`knn()->match()` остаётся пересечением: документ должен удовлетворять обоим условиям.
`hybrid*()` объединяет независимые выдачи на уровне библиотеки, без SQL UNION.

## Переход с alpha.2

Замените `->hybrid($text, $column, $vector, $options)->search()` на
`->hybridSearch($text, $column, $vector, $options)` для сохранения результата с метаданными.
Если нужны только документы, используйте `hybridGet()` либо `hybridFirst()`.
Отдельный метод `hybrid()` удалён без alias; `HybridSearch` остаётся внутренним исполнителем.
Обычные `search()`, `get()` и `first()` сохраняют прежние контракты.
