# 4.0.0-alpha.2

[English](../../releases/4.0.0-alpha.2.md)

API родительского драйвера для последующей интеграции Scout; установка Scout не требуется.
Это предварительный выпуск. Интеграция самого Scout этим релизом не подтверждается.

* Независимые текстовая и векторная выдачи, weighted RRF, детерминированный порядок ID,
  снимки метаданных и пагинация/классификация totals через `HybridResult`.
  Существующий `knn()->match()` сохраняет пересечение.
* Замена локального RT-индекса в режиме обслуживания: пустой staging через CREATE LIKE,
  явное состояние трёх имён, возобновление/откат без автоматического удаления старой таблицы.
  Между rename есть наблюдаемый промежуток недоступности; атомарность и zero downtime
  не обещаются. Distributed-таблицы, кластеры и read/write splitting исключены.
* Ленивые сведения сервера/модулей на соединение, ограниченный кеш read-only probes,
  сохранение причин ошибок и проверка размерности/метрики HNSW. При регистрации SQL не добавлен.
* Накопленные после alpha.1 расширения Schema: настройки ALTER и их чтение, проверяемый
  `change()` для построчного int → bigint и переименование таблицы с Buddy.

См. [API и контракт передачи в Scout](../hybrid-and-index-replacement.md),
[схему](../schema-alter.md) и [руководство перехода с 3.x](../upgrading-3.x-to-4.x.md).

## Проверки и установка

Полный набор на PHP 8.4.19 прошёл с Laravel 11/12/13 на Manticore 28.6.6 и с Laravel 13
на 29.9.0: по **160 тестов / 870 проверок**, без пропусков. Production-установки прошли на обоих серверах, включая
hybrid/probes/clone/switch/rollback. Reader в отдельном процессе, прерывания и настоящая
SQL-ошибка второго rename проверяют ограничения замены. Отдельный экземпляр без Buddy
подтвердил недоступность fuzzy/autocomplete и ошибку rename. Перед публикацией требуется
успешная существующая матрица из восьми CI-job: PHP 8.2/8.3/8.4/8.5 × minimum/latest.
Зависимость от самостоятельного PHP-билдера отсутствует.

```sh
composer require avadim/manticore-query-builder-laravel:4.0.0-alpha.2
```

Вызывающий код alpha.1 сохраняет существующие API. Для объединения нужен новый тип результата
и явная обработка totals окна. Обратное сужение типа не выполняется автоматически.
Импорт, embeddings, очереди, блокировки, согласование записей и очистка старых индексов остаются
приложению. Неявной подмены поискового режима нет. Отчёт живой миграции 3.x → alpha.1 остаётся
историческим свидетельством, а не проверкой Scout или приложения на alpha.2.
